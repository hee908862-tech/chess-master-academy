# 근거 중심 진단 → 훈련 → 재평가

기준 main: `f89218bc7ef3a08bdc021dfa05985b149b10e781` (PR #4 병합 후). 이 변경은 별도 검토 브랜치이며 운영 배포·main 병합을 수행하지 않는다. 기존 QA 수정·계정·진단 이력·학습 기록·문제은행을 유지한다.

## 변경된 흐름

홈의 기본 동선을 기본 진단 → 문항별 근거 → 그 문항에서 이어지는 훈련 → 미노출 적용 → 지연 재평가로 연결했다. 이전 49문항 평가와 기록, AI 대국·퍼즐·아카데미·복기는 계속 접근할 수 있다. 이전 지수와 새 근거를 비교하지 않는다.

- 기본 12문항: 지원되는 6영역 × 600–1200/1200–1800 원본 퍼즐 레이팅 구간. 자료가 모자라면 실제 선정 수를 표시하며 가짜 문제를 만들지 않는다. 추가 확인은 해당 영역의 3개 구간(고급 1800–2400 포함)에서 한 문항씩 선정한다. 시간제한은 없고 제출마다 저장한다.
- 첫 수 성공과 상대 응수 이후 전체 수순 성공을 별도로 기록한다. 정답 후에도 남은 수를 직접 두어야 완주다. 합법 수순 불일치는 미검증 대안이며 열세로 단정하지 않는다. 실제 체크메이트는 규칙으로 검증해 대안도 인정한다.
- `competency-v2` 공통 정의를 진단·훈련·능력 지도·추천에 사용한다. 메이트/다중 수 계산/포획·교환/방어/승격/종반 전술 실행을 관찰하고 전략·계획은 미측정으로 명시한다. `exposedKing`을 방어 능력으로 해석하지 않는다. 종반 전술 성공을 일반 종반 숙련도로 확대하지 않는다.
- 문항 수·독립 국면·첫수·전체·부분 성공을 구분한다. 문항별 난도 구간, 도움 여부, 최초 시도, 노출·응답 시각, 원본 위치/수순/태그/버전, 실제 응답과 기준 응답을 저장한다. 같은 버전 누적 독립 근거도 별도 표시한다. 소표본·동률에서 강점/약점 순위를 강제로 만들거나 임의 레이팅을 계산하지 않는다.
- 완료 진단의 실제 문항에서 훈련을 만들고 추천에 문항 ID와 사유를 표시한다. 원본 반복은 독립 근거나 숙련 상승으로 계산하지 않는다. 공통 태그가 있으면서 같은 관찰 역량의 실제 수순 조건을 만족하는 새 문제로 전이한다. 무도움 새 적용 시도 이후 연결 훈련의 마지막 노출로부터 7일이 지나면 새로운 국면 재평가가 가능하다. 날짜만 남은 이전 노출은 다음 날로 올림해 간격을 줄이지 않는다.
- 비교는 수행 근거의 관찰이며 심리측정 검증·외부 Elo 추정·교육 효과 입증이 아니다. 별도 검증된 장기 전략/계획 과제나 일반 종반 평가를 구현했다고 주장하지 않는다.

## 저장·노출·호환

새 `journey_progress` 테이블에 선택한 전체 스냅샷을 저장한다. 코퍼스가 나중에 달라져도 진행 중인 수순은 바뀌지 않는다. 계정별 기존 progress JSON을 재작성하지 않는다. 튜토리얼만 기존 CAS 저장 경로로 `onboarding_v1` 필드를 추가한다. 시작 시 additive CREATE TABLE만 사용하며 삭제·초기화·원본 퍼즐 변경은 없다.

SQLite BEGIN IMMEDIATE 및 PostgreSQL 계정별 transaction advisory lock 뒤 다른 모드의 노출을 읽고 선정한다. 양 모드의 동시 시작을 직렬화하며 문항 액션은 session ID/revision으로 중복을 거부한다. 예약은 문제 ID와 FEN 앞 4필드로 관리하고 원본 전체 수순의 중간 국면도 포함한다. 실제 제출된 대안 국면도 추가한다. 예약된 미표시 국면까지 보수적으로 제외한다. 기존 기록의 식별 가능한 문제/국면을 제외하고 과거 노출을 충분히 증명할 수 없으면 독립 근거로 승격하지 않는다.

새 모드와 기존 레거시 모드가 동시에 진행되며 레거시 모드에 새 노출이 추가된 경우, 다음 진단 액션에서 독립 적격성을 다시 확인한다. 기존 기록에 없는 노출을 복원하거나, 외부에서 이미 본 공개 퍼즐을 판별할 수는 없다. PostgreSQL advisory lock 분기는 실제 PostgreSQL 통합 환경에서 별도 검증이 필요하다.

## 첫 로그인 안내

명시적인 가입/로그인 성공 후 안전한 경우 짧은 튜토리얼을 연다. 저장 토큰으로 접속하는 기존 계정에는 비차단 초대를 제공한다. 진행 중인 진단·대국이 있으면 자동 안내를 유예한다. 건너뛰기/완료는 버전과 함께 서버 저장하며 프로필·도움말에서 다시 볼 수 있다. 마지막 버튼은 진단 화면만 열고 평가를 자동 시작하지 않는다. 진행 중 대국의 시계가 멈추는 것처럼 표현하지 않는다. Escape, 포커스 순환, 늦은 저장 응답, 모바일을 검증한다.

## 검증과 증거

실제 코퍼스의 후보 수: 메이트 13,000, 다중 수 계산 38,656, 포획 16,912, 방어 3,270, 승격 3,187, 종반 전술 5,222 (중복 태그 허용, 영역 간 고유 문항 합계 아님). 기본 두 난도 구간 모두 후보가 있다. 예를 들어 VEfqe의 2반수 뒤 국면은 d4kK3의 시작 국면과 같아 ID만 제외하면 중복이 생긴다. 전체 수순 국면 제외로 보완했다.

`tests/test_journey.py`: 실제 코퍼스/SQLite의 스냅샷·재시작·중복 제출·다중 수·부분 성공·합법 대안·승격·메이트 해설·이력/계정 보존·지연 재평가·교차 모드 동시 예약·원본 변경 후 복원.

`tests/test_journey_browser.py`: 제어 응답 Chromium 4개와 실제 로컬 API PC/모바일 E2E 2개. 실제 API E2E는 저장/재개→12문항 건너뛰기→0성공 근거→진단 기반 훈련 연결이며 모든 문항 성공을 브라우저로 완주했다는 의미는 아니다. 전체 수순 성공은 별도 API 회귀에서 확인한다. 캡처는 [docs/qa-journey](docs/qa-journey)의 임시 테스트 계정이며 실제 이미지를 확인했다.

추가 bridge/onboarding 회귀 및 기존 전체 테스트를 실행한다. 정확한 최종 수와 실패/미실행 범위는 PR 검증 결과에 기록한다. 운영 실제 브라우저 QA, PostgreSQL 통합, 장기간 교육 효과는 미검증이다. 별도 린트·정적 타입 설정은 없으며 Python 구문·전체 JS 구문·기존 정적 계약 검사를 수행한다.

### 추가 검토 보완: 노출 교집합과 비교 범위

출제 적격성은 `후보 전체 수순 국면 ∩ 기존 노출·예약 전체 수순 국면 = 공집합`일 때만 인정한다. 시작 위치뿐 아니라 양쪽의 모든 중간 위치와 종료 위치를 포함한다. 순서를 뒤집어도 동일하며, 시작점이 다르지만 중간에 같은 위치로 합류하는 문제도 신규 독립 평가에서 제외한다. 기존 연습 카드의 복습 기능은 유지한다.

위치 동등성은 python-chess가 생성한 정규 FEN의 **기물 배치·차례·캐슬링 권리·합법 앙파상 권리** 네 필드로 정의한다. 반수 시계와 수 번호는 노출 식별에서 제외한다(50수 규칙 등 실제 대국 판정에는 계속 사용). 합법적인 앙파상 가능성이 없는 표시는 정규 FEN에서 `-`로 처리된다. 같은 테마·전술 원리·재료 구성·평가값이라는 이유만으로 동일시하지 않으며, 좌우 반사나 색 교환도 적용하지 않는다. 반대로 차례나 실제 캐슬링/앙파상 권리가 다르면 동일 위치로 취급하지 않는다. 원본 수순 밖의 가능한 모든 변형까지 탐색하지 않는다.

능력 지도 성공률은 `(competency_version, assessment_scope)`별로 분리한다. 상황 대국은 첫 수/전체 원본 수순과 다른 범위다. 구형 버전, 버전/범위 미기록, 현재 버전의 첫 수 판단은 각각 별도 참고로 표시하며 현재 전체 수순의 분모·이전/최근 비교·보완 우선순위에 넣지 않는다. 동일 그룹에서 도움 없는 적격 시도만 사용하고, 같은 위치는 최신 적격 시도 하나로 축약한다. 최근 성공률에는 서로 다른 5개 국면, 이전/최근 비교에는 각각 5개씩 총 10개 국면이 필요하다. 비교 가능한 근거가 부족하거나 우선순위가 동률이면 순위를 단정하지 않는다. 기존 원본 시도 기록은 보존한다.

`tests/test_evidence_boundaries.py`는 실제 코퍼스의 VEfqe/d4kK3 문제쌍 양방향, 서로 다른 시작점에서 중간에 합류하는 합법 수순 양방향, 동일 원리지만 겹치지 않는 대조 문제, FEN 권리/시계 경계, 구형 첫 수 성공과 새 전체 수순 성공/실패 혼합, 반복 국면·상황 대국의 별도 집계를 검증한다.

추가 검토 보완 최종 검증: 기존과 같은 임시 SQLite/실제 Stockfish 환경에서 전체 **191 passed**, 357.42초(새 경계 회귀 14개 포함). Python AST 43개·JS 구문 13개·기존 정적 검사 6종·diff 검사 통과. 처음 보완 검증의 1개 실패는 버전/범위가 없는 실패 기록을 우선 추천하던 기존 fixture였다. 현재 버전 전체 수순 실패 fixture로 기존 유효 우선순위를 검증하고, 구형/미기록/첫 수 실패가 순서를 바꾸지 않는 별도 3개 회귀를 추가했다. 모바일 능력 지도에서 참고/현재 전체 수순 표시를 직접 확인했다. 운영 PostgreSQL 및 배포 후 검증은 여전히 미실행이며, main 병합·배포는 하지 않는다.
