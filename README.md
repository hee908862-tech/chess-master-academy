# Chess Master Academy v9.0 — 모바일 / Lichess 실전 퍼즐 기반 개편

기존 v8.1 기반 누적 코드입니다. 계정/PIN/PostgreSQL 상태 테이블은 변경하지 않습니다. **기본 배포 ZIP에는 공개 퍼즐 원본이 포함되지 않습니다.** (원본 다운로드가 현재 제작 환경에서 차단됨.) 따라서 원본 데이터를 먼저 가져와야 신규 퍼즐·15문제 아카데미·새 평가가 작동합니다. 빈 `puzzles_lichess.jsonl` 상태에서는 가짜 문제로 대체하지 않습니다.

## 개선

- 모바일 하단 네비게이션 수평 스크롤, 오프닝/복기 메뉴 직접 접근, 터치 가능한 체스판, 세로 레이아웃, 안전영역 적용.
- Lichess 공개 CC0 퍼즐 CSV 기반 콘텐츠 파이프라인. `mateIn1`부터 `mateIn5`, 포크, 핀, 스큐어, 발견공격, 이득, 방어, 엔드게임, 승격, 무승부, 희생 등 테마 필터.
- 원본 CSV의 문제 ID·난이도·정답 수순을 가져오고 Python 체스 엔진으로 **모든 수의 합법성 검사**. 원본 CSV의 수순 첫 수는 상대방의 마지막 수이므로 보드에 먼저 적용함.
- 과목 클릭 → 난이도(입문/중급/고급) → 중복 없는 무작위 15문항. 완료 기록은 기존 계정의 progress JSON에 저장. 15문항 풀이=세션 완료, 12문항 이상 첫 시도 성공=숙련.
- 문제 판정 시 원본의 **한 가지 검증 수순**을 사용함. 다른 동등한 최선 수를 완전하게 인정하는 기능은 **미완료**. 실제 Stockfish로 대안 수를 확인하는 별도 평가 작업이 향후 필요.
- v8의 '나이트 꺼내기' / '무의미한 폰 밀기' 진단 문제를 폐지. 실제 전술 포지션의 7영역×7난이도(레이팅 대역)에서 출제. 각 문제는 첫 후보 착수 판정 방식이며, 시간과 정오답 기반 계산은 기존 실험적 내부 지수 유지. **공식 Elo 아님**.
- 기존 '메이트 인 3' 4종을 랜덤 퍼즐인 것처럼 보여주는 화면은 숨김. 공개 DB의 `mateIn3`를 선택할 수 있으며, 조건에 맞는 원본 퍼즐 데이터를 수입하면 다양한 3수 메이트가 나타남.

## 매우 중요: 공식 퍼즐 데이터 확보

1. https://database.lichess.org/#puzzles 접속 → `lichess_db_puzzle.csv.zst` 다운로드. Lichess 공개 퍼즐은 CC0 라이선스입니다.
2. PC에서 7-Zip 등으로 `.zst` 압축을 풀어 `lichess_db_puzzle.csv`를 얻습니다. CSV는 크기가 매우 클 수 있습니다. 사용 가능한 저장 공간을 확인하세요.
3. 다운로드한 본 프로젝트의 루트 폴더에서 터미널 명령 실행:

   `python import_lichess.py "C:\\다운로드경로\\lichess_db_puzzle.csv"`

   Linux/macOS에서 `zstd` 실행 파일이 있으면 `.csv.zst` 경로를 바로 인수로 쓸 수 있습니다.
4. 동일 폴더에 **`puzzles_lichess.jsonl`** 생성. `RatingDeviation<=135`, `Popularity>=65`, 풀이 수 45회 이상이며 테마·레이팅별로 무작위 표본을 선별합니다. 부정확한 평가 문제가 섞일 가능성을 완전히 없애는 품질 보증은 아닙니다.
5. 해당 JSONL도 `server.py`, `v9_server.py`, `assessment_v8.py`, `v8_server.py`, `public/` 등 **전체 프로젝트와 함께 GitHub에 업로드**하세요. GitHub 웹 UI에서 파일 제한에 걸릴 경우 표본 한도 `CAP=200`을 줄여 다시 생성합니다.
6. 기존 Render 서비스에 배포된 뒤 `https://chess-master-academy.onrender.com/api/v9/catalog`을 열어 `ready: true`, `count: ...`인지 확인하세요. 과목별로 최소 15문항이 있어야 해당 난이도를 시작할 수 있습니다. 진단은 7개 영역 각 7개 레이팅 구간에 문제 1개 이상이 있어야 시작합니다.

### 출제 원칙

Lichess 데이터는 실전 포지션이므로 이전처럼 텅 빈 임의 배치나 근거 없는 폰 전진을 정답으로 출제하는 방식보다 낫습니다. 하지만 퍼즐의 유일 정답 수순이 모든 동등한 최선 수를 포괄한다고 보장할 수 없고, `endgame` 테마도 완전한 테이블베이스 학습과 다릅니다. 이 한계를 UI에도 안내합니다.

## 배포

기존 저장소에 파일을 병합합니다. v8.1에서 만들어진 기능도 모두 포함된 누적 패키지입니다. 반드시 PostgreSQL DB를 백업하고 `DATABASE_URL` 변경 금지. ZIP의 상위 폴더가 아니라 **그 안의 파일과 폴더**를 GitHub 저장소 루트에 올립니다.

Dockerfile에는 `v9_server.py`와 `puzzles_lichess.jsonl` 복사를 추가했습니다. 재배포 후 기존 사용자 로그인 및 기존 데이터 유지 여부 확인이 필요합니다.

## 테스트의 실제 범위

Python compileall / Node.js `--check` / 정적 HTML 요소 검사만 수행했습니다. 현재 제작 환경에 `python-chess`가 없고 데이터 원본을 내려받을 수 없으므로 실제 15문항 완주와 전 영역 엔진 평가를 통합 검증하지 못했습니다. 새로운 코드 역시 **배포 후보**이며 고품질 완성 시스템이라고 보증하지 않습니다.
