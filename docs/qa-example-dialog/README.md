# 기초 예시 팝업 QA

PR #52가 병합된 main `2bcf6c9`에서 이어지는 UI 변경입니다. 기존 17개 관계형 레슨, 예시 FEN/합법 수순, 안내 따라 하기와 같은 문제의 독립 확인 계약은 유지합니다.

## 동작

- 첫 설명은 제목이 있는 native modal dialog로 열리고 무음 보드 애니메이션이 자동 재생됩니다. 마지막 장면에서 멈추며 연습을 자동 완료하거나 자동 진입하지 않습니다.
- `연습 시작`은 기존 안내 따라 하기로, `건너뛰기 · 혼자 풀기`는 기존 독립 확인으로 이동합니다. `다시 보기`는 첫 장면부터 재생합니다. 일반 정답/직전 문제 시연도 같은 팝업으로 열립니다.
- ESC/닫기는 학습 단계를 변경하지 않습니다. 설명 단계에 남아 다시 보기/연습 시작/건너뛰기를 선택할 수 있습니다. 같은 연습 세션은 같은 탭에서 이동·새로고침해도 강제로 다시 열지 않습니다. 새로 시작한 연습에는 새 세션이 있으므로 다시 소개합니다.
- 팝업 표시 여부만 sessionStorage와 메모리에 저장합니다. 서버의 시연 도움 기록 및 학습 상태는 기존 API 계약을 그대로 사용합니다. 진단·점수·계정 연결 모델은 바꾸지 않습니다.
- OS와 앱의 움직임 줄이기 설정에서는 정지된 첫 장면과 이전/다음 단계 조작을 제공합니다. 배경 입력·스크롤은 차단하고 제목으로 포커스를 옮기며 Tab 순환, ESC, 닫은 뒤 원래 버튼 복원을 제공합니다.
- 창 숨김은 재생을 멈추며 자동 재개하지 않습니다. 닫기/라우트 이탈/로그아웃은 타이머와 움직이는 말 표시를 취소합니다. 렌더링 중인 말은 modal top layer 안에 그리며 예시 전환은 기존 효과음을 호출하지 않습니다.

## 근거

[Chess.com 공식 Lessons 안내](https://support.chess.com/en/articles/8609703-how-do-lessons-work-on-chess-com)는 설명과 상호작용 연습을 결합합니다. [Lichess 공식 learn](https://lichess.org/learn)도 직접 열람했으나 웹 본문에서 동적 세부 UI를 확인할 수 없었습니다. 이번 자동 팝업은 사용자의 명시적 후속 요청에 따른 구현이며, 두 사이트가 동일한 자동 팝업을 사용한다고 주장하지 않습니다. 외부 영상·음성·자료 복제는 없습니다.

## 확인 범위

`tests/test_example_dialog_browser.py`는 실제 로컬 API와 Chromium으로 자동 재생, 무음, 움직이는 말의 modal 배치, OS/앱 움직임 감소, 초점 복원/순환, 배경 차단, 기록 불변, 중복 방지, 새로고침/뒤로/라우트/로그아웃/재시작을 검사합니다. 기존 관계형 레슨·시연·기초 이동·보드 애니메이션 검사를 함께 실행합니다. 최종 head 전체 CI 결과는 PR에 기록합니다.

320×650, 390×844, 844×390, 1366×768 및 390×844의 CSS 125% 확대를 검사했습니다. 작은 화면에서는 팝업 내부를 스크롤하며 모든 활성 버튼의 중심을 elementFromPoint로 확인합니다. 첨부 화면은 자동 재생을 일시 정지한 실제 Chromium 출력입니다.

물리 Kakao/iOS 및 보조공학 실기 검증은 아닙니다. 마지막 독립 단계는 기존과 같은 문제의 안내 제거이며 새 위치의 전이 학습이나 숙련 인증이 아닙니다.
