# 대국 복원 상태 안내

## 원인과 변경
운영에서는 부모가 새로고침 후 30~40초 동안 초기판과 게스트 안내를 보고, 이후 기존 대국이 복원됨을 확인했다. 소스에서는 초기 `/me` 대기와 이어지는 `/game` 대기 중 `gameStatus`가 정적 게스트 문구에 머물렀다. 서버 지연 자체의 원인은 이 조사에서 확정하지 않았다.

- 인증 확인 / 저장 대국 조회 / 조회 실패 / 조회 완료를 구분한다.
- 확인 전 초기판은 공간을 유지하며 숨기고, 새 대국 및 대국 입력은 확인 전 잠근다. 실패 시 조회 재시도를 제공한다.
- 같은 계정의 이미 확인된 위치는 재조회 동안 보존한다. 다른 계정 확인 중에는 이전 위치를 숨긴다.
- 조회 요청 세대, 계정 토큰, 착수 revision을 검사해 오래된 응답을 무시한다.
- `/game` 읽기에 기존 30초 읽기 제한을 적용한다. 엔진 착수 요청 시간 정책은 그대로다.
- 서버, 저장 계약, 인증 정책, 게임 규칙, 도움 집계는 변경하지 않는다.

## 검증 범위
임시 SQLite 계정 + 일반 headless Chromium. 신규 지연/실패 테스트는 읽기 응답을 통제하며 POST 0을 확인한다. 기존 대국/프리무브/로그인 검사는 로컬 임시 계정으로 실행한다. 운영 계정에 접근하지 않았다.

캡처는 실제 Chromium 화면: 대기 PC, 복원 후 390×844 / 1280×720. 실제 이미지를 열어 위치와 배치를 확인했다. 물리 모바일 또는 운영 재검증을 의미하지 않는다.

최종 코드/테스트 SHA `10d018f505acd71b35ade76157c20bd078ba937d`: 관련 회귀 **67 passed / 0 failed / 0 skipped**, 227.27초. Node 구문 검사 3파일 및 git diff --check 통과. 실행 결과는 results.log 참조. 이전 전체 630 통과는 PR27 결과이며 이번 변경의 전체 회귀 결과로 인용하지 않는다.

실제 Docker 이미지 빌드 및 PostgreSQL: 미실행. 루트/Docker 저장소 여유 0. 실제 Docker COPY 범위로 만든 격리 payload의 모듈 포함/import 및 부정 대조 검사를 대신 수행한다. 이것을 이미지 빌드 통과로 간주하지 않는다.
