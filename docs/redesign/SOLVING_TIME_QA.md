# 풀이 시간 점수와 준비 단계 검증

기준: PR46 `e00add11b17edb00a694c34f57a3b8a9976720a4`. 실제 계정·PIN·기보·답안·기준선·점수를 삭제하거나 재채점하지 않았다. 모든 쓰기 검사는 격리 SQLite/합성 계정이다.

## 실제 저장 경로

`journey_server.finish_item`은 문항 종료 때 `solving_time`을 고정하고 새 `solving_score`를 feedback과 문항에 저장한다. `finish`는 모든 배정 문항으로 회차 점수를 만들고 `results`에 저장한다. 동일 GET 결과를 확인했다. 브라우저는 서버 계산값을 표시하며 재계산하지 않는다. 새 초기 과정의 고정 결과에도 전체 배정 기반 점수를 별도 저장한다.

새로 시작한 진단만 `solving-performance-v1`을 고정한다. 배포 전 진행 중 세션과 이미 초기화된 초기 과정은 기존 규칙을 유지한다. 기존 40/60 수행점수도 원본/비교 참고로 남으며 새 점수보다 뒤에 표시한다. 과거 시간을 추정하지 않는다. 초기 과정에 이전 시간 조건 관찰이 섞이면 전체 새 점수는 보류하고 새 회차 점수만 제공한다.

산식은 [모델 문서](SOLVING_SCORE_MODEL.md) 참조. A/B는 동일 고정 배정 집합·분모를 사용한다. 미확정 하나라도 있으면 최종값은 null이며 성공 문항만으로 시간 가산을 평균내지 않는다. 비교 메타데이터에는 산식·시간·목표시간 정책·문제은행·평가 범위·판정 규칙·문항 집합 해시를 저장한다. 새 점수를 이전 성장 시리즈에 섞지 않는다.

## 저장 후 GET까지 확인한 예

메이트, 외부 난도1200, 선택 가능한 내 수1이면 T=45초다. 아래 시간 입력은 결정적인 격리 API 검사용 서버 시계이며 실제 사용자가90초 동안 푼 관찰이 아니다. SQLite 저장과 다시 조회를 검증했다.

| 사례 | A | B | 기본점 | 시간 가산 | 최종 |
|---|---:|---:|---:|---:|---:|
| 정답10초 | 1 | 1 | 2850 | 150 | 3000 |
| 정답90초 | 1 | 0 | 2850 | 0 | 2850 |
| 첫 수 목표 실패10초 | 0 | 0 | 1 | 0 | 1 |
| 선택 수2회 중1회 확인 후 중단 | .25 | 0 | 713 | 0 | 713 |
| 판정 미확정 | null | null | null | null | 보류 |
| 정답·중간 중단 표시 | 1 | 0 | 2850 | 0 | 2850 |
| 정답·시간 누락/큰 저보고 | 1 | null | 2850 | null | 보류 |
| 빠른 정답1개+오답1개 | 평균 .5 | 평균 .5 | 1426 | 75 | 1501 |
| 빠른 정답1개+미확정1개 | null | null | null | null | 보류 |

실제 로컬 Chromium과 실제 API에서도 정답 저장값3000=2850+150, 새로고침 후 정답2850=2850+0을 확인했다. 문항 종료 뒤 체류 시간은 저장값에 추가되지 않았다. 정상1초 미만 값은 소수로 보존하며, 실제0ms는 분해능 미만으로 별도 보류한다.

난도는 T에만 영향을 준다. 같은 목표 완수의 A는 난도와 무관하게1이며 고난도 부분 수행에 임의배수를 주지 않는다. 이번 변경은 시간 반영 수행점수이고 난이도 보정 능력 추정은 아니다.

## 시간 상태와 공정성

1. 국면 제공 후 기물 이미지 load/decode를 확인한다. 실패하면 시작하지 않고 다시 준비 버튼을 제공한다.
2. 소유 세션·문항·revision 확인 후 서버 준비 시각을 한 번만 기록한다. 보드를 보여주는3초 동안 문제지시와 입력을 잠그고 텍스트 카운트다운을 표시한다. 숨겨진 탭에서는 준비 카운트다운을 진행하지 않는다. 입력 가능 시 지시·가산 기준시간·누적 풀이 시간이 표시된다.
3. 합법 입력 확정 시 로컬 시간을 고정한다. 판정·상대 자동 응수·모션 동안은 더하지 않으며 입력 가능할 때 이어 잰다. 서버는 엔진 작업 전에 접수 시각을 확보하고 작업 뒤 다음 구간을 연다. 순수27초 엔진 대기 대역 검사에서 풀이10초를 유지했다.
4. 성공/실패/건너뛰기/미확정으로 문항 종료 시 고정한다. 다음 문항은 사용자 버튼으로만 진행한다. 다음 내부 묶음도 마지막 다음 조작 이후 같은 흐름으로 이어지며 다시3초 준비한다.
5. 중단·새로고침·탭 비활성·메뉴 이동은 해당 시도의 시간 가산 제외를 유지한다. 확인된 수행에는 중단 벌점이 없다. 명시 중단은 B0, 실제 측정 오류는 B미확정으로 구별한다. 이전 결과 복기·분기·재검증 대기는 시간을 더하지 않는다.

클라이언트 시간은 완전히 신뢰할 수 없다. 서버는 누적·순서·상한·소유권과 경과시간을 대조한다. 준비 호출이 최초 제공보다5초 넘게 늦거나, 비중단 구간의 보고 시간이 서버 경과와2초 넘게 차이나면 보수적으로 시간 평가를 보류한다. 이 수치는 저자 설계 허용오차다. 느린 이미지·네트워크도 이 조건에 해당할 수 있으므로 부정행위나 사용자 잘못이라고 표시하지 않는다. 알려진 중단은 서버 하한 추정에서 제외한다. 악의적인 브라우저를 완벽히 검증하는 보안/감독 시스템은 아니다.

## 흐름 일관성

- 진단: 새 버전만 시간 가산. 기존 진행은 기존 버전. 중복 제출은 revision으로 한 번만 반영한다. 잘못된 선택적 시간값은 합법 답안을 거부하지 않고 시간 평가만 보류한다.
- 훈련/퍼즐: 기존 연습·독립 퍼즐 규칙을 유지한다. 새 진단 산식을 모든 모드에 적용하지 않는다. 도움/정답 보기/재도전은 기존 노출 보호를 유지한다.
- 복기/해설/분기: 이미 종료된 진단 시간을 멈춘 채 읽거나 탐색한다. 원래 점수·답안은 변경하지 않는다. 분석 노출 이력은 기존 방식으로 이후 독립성을 구분한다.
- 이전 전체 시도 패널: 새 풀이 시간을 미측정 활동 시간으로 잘못 설명하지 않도록 표시를 분리했다. 새 점수는 결과의 앞쪽에, 원본 점수는 별도로 남긴다.

## 검사와 한계

새 산식 단위38개, 시간 단위32개, 시계 컴포넌트 브라우저10개, 점수 컴포넌트 브라우저12개가 통과했다. 실제 API 저장·보존14개와 선택적 시간 회귀1개 총15개 통과. 실제 로컬 API/Chromium 지연·복원2개도 통과했다. 실제 앱 브라우저7개는 PC1366×768/1366×540, 모바일 에뮬레이션360×800/390×844/800×360, 재접속, 느린 통신을 검사했다. 컴포넌트에서 키보드·200%확대·긴 문장·이미지 실패·반복 준비·미측정과 결과 고정도 확인했다. 기기 소리는 꺼도 상태가 텍스트로 전달된다.

실패를 숨기지 않았다: 기존 무조건 미검증을 기대한 랜덤 문항 검사는 PR45의 메이트 증명으로 실패할 수 있어 '검증기 unavailable' 대역을 명시했다. old thinking_time을 새 세션에서 기대하던 테스트는 새 계약으로 갱신했고 구버전 실제 세션 보존은 별도로 검증했다. 숫자3,000의 쉼표 기대값과0ms/null 구분 fixture도 수정했다. 새 시계의 결과 복원, 알려진 중단을 저보고로 오인하던 처리, 중복 준비의 불필요한 DOM 재렌더는 통합 중 수정했다.

실제 Stockfish 검사는 공개 합성 국면 검증이며 시간 전체 흐름의 엔진 대기 재현은 명시적 대역이다. 원래 운영 엔진 실패를 재현했다고 주장하지 않는다. 운영 브라우저의 새 점수 쓰기, 실제 모바일 기기, 실제 초보자 관찰, PostgreSQL 부하·다중 인스턴스 검증은 미실시다. 기존 운영 프록시403을 우회/반복하지 않았다. Render 자동 배포/Live 확인과 운영 UI 검수는 구분한다.

최종 선택 회귀146개는 최초142개 통과·4개 실패였다. 네 실패는 기존 묶음전환 fixture가 새3초 준비 중 직접 skip을 호출해 정상409를 받은 것이었다. 준비 완료를 기다리도록 fixture만 수정했고, 해당 브라우저6개와 저장·보존API14개를 함께 재실행해20개 모두 통과했다. 새 초기 기준선 비교 메타데이터도 이 재실행에 포함된다. 최종 선택 범위146개 모두 통과 근거가 확보됐으며, 별도 시계/점수 컴포넌트22개·앱 브라우저7개·시간통합2개와 범위를 구분한다. Docker COPY 패키징 검사5개가 포함되며 실제 컨테이너 빌드는 로컬에서 수행하지 않았다.
