# PR43 후속: 초기 진단 진입과 훈련 출처 연결

## 변경과 보존

- 홈은 현재 고정 기준선 ID와 추천 report/item 출처가 모두 일치하는 훈련 경로의 완료만 다음 적용 단계로 인정한다. 옛 완료 경로, 출처 불일치, 기준선 ID 없는 경로는 인정하지 않는다.
- 기준선 ID는 저장된 원본의 버전/corpus/고정 시점/문항 참조로 읽기 시 도출한다. 과거 점수와 기준선은 다시 저장하거나 재계산하지 않는다.
- 서버는 소유 계정의 검토된 기준선과 문항 소속을 검증한다. 같은 출처의 미완료 경로는 사용자가 결과에서 명시적으로 요청할 때만 현재 기준선에 연결한다. 기존 완료 경로의 소급 연결은 하지 않는다. 다른 기준선/진행 중 활동 충돌은 보존하고 거절한다. 같은 완료 요청은 멱등 처리한다.
- 개념 확인과 이후 경로 계속 버튼을 현재 활동/선택 영역에 제공한다. 평가·착수 규칙은 그대로다.
- 새 방문자의 #diagnosis/initial에 목적, 48 유효 관찰과 최대 24 대체, 저장 범위, 로그인 없이 시작, 선택적 계정 로그인을 표시한다. 일반 진단에도 초기 경로를 제공한다. 페이지 조회로 정체성을 만들지 않으며 기존 guest/start 흐름은 명시 버튼에서만 실행한다. 생성 뒤 원래 초기 경로를 유지하며 풀이 시작은 별도 명시 버튼이다.
- 결과에는 ‘이번 평가 범위의 수행 점수’, 기초 600–1199 / 응용 1200–1799 범위, 40/60 수행 비율 환산, 구간 내 난이도 미보정을 표시한다. **난이도 보정된 능력 추정은 여전히 미완성이다.** 3000은 체스 전체 숙련이 아니다. 공식/점수 버전 변경 없음.

## 검증

로컬 격리 SQLite 및 Chromium. 기존 운영 계정/진행 중 QA 세션에 쓰기 없음.

- 초기 모델/훈련 연결/출처 검증 21 통과. 실제 출처 기반 API, 미완료 경로 명시 연결, 옛 완료/위조/다른 소유자/충돌 보존, 개념 확인 지연 및 다음 단계 PC/모바일.
- UI/게스트 보안 30 통과: 28개 첫 실행 통과, 기존 결과 레이아웃 2개는 테스트의 기초 입문이 게스트 정체성 생성이라고 가정한 fixture를 수정하고 재실행 통과. 실제 명시 게스트 시작으로 설정한다. 신규 48문항 완주는 이 테스트에 포함하지 않는다.
- 신규 브라우저 1366×768, 360×800에서 조회만으로 생성 없음, 중복 클릭 생성 1회, 초기 경로 복원/새로고침/활성 진단 보존. 선택적 로그인 복귀 목적지, 생성 503 실패 표시. 결과 360/390폭의 차트 글자·가로 넘침 검사. 훈련 추천 UI 테스트는 API doubles를 사용하며 서버 소유권 검사는 별도 실제 API 검사다.
- 게스트 연결→로그아웃→새로고침/다른 탭 차단→재로그인은 로컬 격리 fixture로 검증한다. 운영 실계정 검증이 아니다.
- 캡처: captures/initial-followup/anonymous-*는 기록 없는 로컬 브라우저, result-390은 합성 기준선 GET double. 실제 모바일 기기나 초보자 관찰 아님.

## 운영 재검수 경로와 한계

1. 기록 없는 별도 브라우저에서 #diagnosis/initial 및 #diagnosis의 초기 진입/저장 설명 확인.
2. 명시 게스트 시작 후 초기 경로 복귀, 두 번째 버튼으로 첫 묶음 시작 및 복원 확인.
3. 옛 훈련 완료만 있는 새 기준선은 결과의 맞춤 훈련을 안내해야 한다. 현재 출처 연결 완료 후에만 적용으로 전환한다.
4. 결과 수행 점수/난이도 한계 문구 확인.

기존 실행 환경 운영 CONNECT 403 제한을 반복하거나 우회하지 않았다. 부모 운영 점검은 읽기 전용으로 제한되었으므로 운영 신규 48완주, 새 기준선 훈련 쓰기 연계, 계정 연결 쓰기는 미검증이다. 원본 Library 이미지는 이 환경에서 열람하지 않았다. 이전 운영 API 지연이 해결됐다는 주장을 하지 않는다.

최종 검사 합계는 중복 재실행을 제외한 **65개 통과**다 (21 + 30 + 14). 마지막 14개는 Docker COPY 자산/모듈/격리 런타임과 대국 분석 회귀이며 실제 Stockfish 메이트·스테일메이트 2개를 포함한다. 나머지 엔진 실패·대기 검사는 doubles다. Docker 이미지 실제 빌드나 운영 PostgreSQL 검사는 아니다. JS 구문 및 git diff --check 통과. 초기 실패는 숨겨진 개념/다음 단계 버튼 2건과 정체성 생성에 대한 결과 fixture 가정 2건으로, 수정 후 해당 검사를 모두 재통과했다.
