# 초기 관찰 과정과 실전 장면 연결

## 범위와 보존

PR41/42 이후 기준 main `9890d5a72cc7eb5a36bb07db9212850c1e175e24`에서 추가한다. 기존 진단 회차, 판정, 점수, 활성 세션, 훈련 경로, 계정 및 게스트 소유권은 그대로 둔다. 별도 DB 마이그레이션 없이 기존 소유자별 JSON 안에 `initial_profile`을 추가한다. 기존 결과를 수정하지 않으며 새 과정 시작 시 같은 자료·점수·분야 버전의 유효 관찰만 참조한다. 활성 세션이 있으면 새 배정/중단/결과 확정을 거부한다. 새 필드를 읽지 않는 이전 앱에서도 원래 기록은 보존된다.

## 완료 모델

- 범위: 현재 검증된 전술·수순 실행 6분야. 오프닝 이해, 전략·계획, 일반 종반 전체는 미측정이다. 체스 전체 실력 진단 완료라고 부르지 않는다.
- 고정 관찰 범위: 분야별 기초(문제은행 600–1199) 4개와 응용(1200–1799) 4개, 합계 48개. 이는 저자 설정이며 검증된 정밀도 또는 정확도 기준이 아니다. 하위 유형을 모두 측정했다는 주장도 하지 않는다.
- 검증된 오답/비메이트도 유효 관찰이다. 정답 개수로 완료하지 않는다. 같은 문제/수순 중간 위치 중복, 도움, 앱 내 기출, 건너뛰기, 부분 수행, 판정 미확정은 별도 제외한다. 앱 밖 노출은 알 수 없다.
- 시작 시 부족한 필수 수 + 최대 24개의 대체만 배정한다(신규 최대 72). 분야별 최초 부족분을 최대 8개씩 먼저 탐색하고 이후 최대 4개씩 보충한다. 사용자는 부족 분야로 직접 갈 수도 있다. 총 상한은 바뀌지 않는다.
- 중단/문제 부족/상한 도달이면 판단 보류로 결과를 본다. 진행 중 묶음은 언제든 저장·복귀하며, 과정 중단은 현재 묶음을 마친 뒤 선택한다. 실패를 성공으로 바꾸거나 무한 재시작하지 않는다.
- `not_started → in_progress → ready 또는 held → reviewed`이다. 결과 확인 POST에서 기준선을 고정한다. `ready`는 관찰 범위 충족이며 실력 확정이 아니다. 동일 요청 반복은 기존 기준선을 반환한다.
- 최초 근거 보충은 기존 성장 재진단의 훈련 5개 게이트와 분리된다. 기존 성장 재진단 규칙은 그대로 유지한다.

## 점수와 근거

기존 `skill-index-v1`의 기초 40%·응용 60%, 분야 동일 비중을 그대로 사용한다. 값은 `1 + round(2999 × 수행비율)`이며 1점 차이 정밀도·Elo·완전 숙련을 의미하지 않는다. 새 기준선은 `initial-baseline-v1`, 표집은 `initial-targeted-v1`로 구분한다. 원래 개별 회차 점수와 성장 차트에 혼합하지 않는다.

각 분야 두 구간의 4개 고정 슬롯을 유지한다. 아직 관찰하지 못한 슬롯은 계산 안에서만 미확정으로 넣으며 원문항·예약·출처·기록으로 저장하지 않는다. 모든 필수 슬롯이 유효해야 해당 분야 점수를 표시하고 모든 분야가 충족돼야 종합 수치를 표시한다. 예: 각 구간 1개씩만 성공한 총 12개 관찰은 3000점이 아니라 보류다. 각 구간 2성공·2검증오답인 48개 관찰은 1501점이다. 모든 48개 성공은 해당 범위 3000점이며 범위 밖 숙련은 알 수 없다. 누락 결과의 상하 경계는 통계적 신뢰구간이 아니다.

결과에는 측정 범위, 관찰 수·난도, 분야 수치 또는 보류, 대표 원국면/실제 착수/당시 판정, 원문항 기반 훈련을 둔다. 첫 결과 단일 점 성장 그래프는 강조하지 않는다. 비교 가능한 개별 회차 기록이 둘 이상일 때만 기존 성장 차트를 표시한다.

## AI 대국 관찰

추가 Stockfish 호출 없이 저장된 기보와 합법수 규칙으로 한 수 메이트 기회(성공/다른 수)와 피할 수 있었던 상대 한 수 메이트 허용만 분류한다. 모든 여섯 분야에 정확도를 일괄 합산하지 않는다. 각 관찰에 원 FEN, 실제 수/후속 FEN, 가능한 메이트 또는 회피 예시, 규칙 출처, 도움 기록, 대국 조건을 연결한다. 연속/동일 국면의 같은 유형은 한 묶음으로 표시한다. 기회가 없었던 기술은 미측정이며 반복 장면은 추가 연습과 새 확인 문항으로만 연결한다.

조회는 소유자 인증을 거친 읽기 전용이며 진단 기준선/게임 평점/훈련 기록에 쓰지 않는다. 80개 사용자 수, 400ply, 20,000개 규칙 적용 예산을 두고 초과/불완전 기보는 부분/미관찰로 표시한다. 검증하지 못한 나머지를 실패나 대등으로 해석하지 않는다. 기존 엔진 예산·타임아웃·인증 규칙은 변경하지 않는다.

## 참고와 한계

- [ETS Standards](https://www.ets.org/content/dam/ets-org/pdfs/about/standards-quality-fairness.pdf): 분야별 해석에는 별도 타당도/신뢰도 근거가 필요하다. 본 기준은 아직 경험적 교정이 아니다.
- [ETS CBT 2011](https://www.ets.org/Media/Research/pdf/CBT-2011.pdf): 폭넓은 탐색 이후 표적 확인 및 종료 조건을 참고했다. 해당 측정모형을 구현했다는 뜻은 아니다.
- [GOV.UK task list](https://design-system.service.gov.uk/components/task-list/): 독립 과제 상태와 바로가기 원칙 참고.
- [Lichess accuracy](https://lichess.org/page/accuracy): 정확도는 국면 복잡성 영향을 받으며 시험 점수/실력 자체와 동일하지 않다.
- [Chess.com Insights](https://support.chess.com/en/articles/8708925-what-is-insights-on-chess-com): 전술 기회 연결 참고. 해당 제품은 컴퓨터 상대 대국을 제외하므로 우리 AI 관찰의 검증 근거로 삼지 않는다.

공식 문구/그림을 복제하지 않았다. 모바일은 Chromium viewport 에뮬레이션이며 실제 기기·초보자 관찰을 대신하지 않는다. 기존 운영 API 지연/복기 평가 성공은 별도 운영 확인 대상이다. 이 실행 환경의 운영 프록시 차단은 재시도하거나 우회하지 않는다.
