- Render 로그에서 2026-10-22 00:00 UTC ~ 2026-10-23 03:15 UTC 범위의 `TEST3` 문자열을 검색했다. 결과는 logs=[] / hasMore=false였다. 이는 계정 기록이 없다는 뜻이 아니다. 현재 코드의 엔진 시간 로그는 계정별 답안/점수 감사 로그가 아니다.
- 현재 연결 도구에는 운영 DB SQL/SSH 실행 동작이 없다. 로컬 Render CLI, 제공된 RENDER_API_KEY, DATABASE_URL도 없다(값을 조회하거나 출력하지 않고 존재 여부만 확인).
- 운영 HTTP 프록시 403의 기존 제한은 반복/우회하지 않았다. 계정 로그인 비밀을 요청하거나 새 관리자 API를 만들지 않았다.

따라서 TEST3의 문항 ID/제출수/도움/재시도/포함·제외/당시 기준선 연결을 직접 확인하지 못했다. 사용자의 ‘메이트를 틀린 기억’이나 3000 표시를 오류/정상으로 확정할 수 없다. 기록 수정, 재채점, 계정 초기화는 수행하지 않았다.

## 코드에서만 확인한 설명 가능성

PR44 기준 초기 프로필은 호환되는 최초·무도움·미노출 관찰 중 분야/난도별 정해진 수를 선택한다. 정상적으로 검증된 오답(verified_error, verified_non_mate)은 0의 수행값으로 포함되며, 엔진 미확정·건너뜀·부분 실행·도움·중복은 별도로 제외된다. 따라서 사용자가 오답으로 기억하는 문항이 실제로 제외 항목이었다면, 선택된 메이트 관찰만 모두 완주하여 메이트 수행값 3000과 병존할 수 있다. 이것은 TEST3에서 확인한 사실이 아닌 코드에 근거한 가설이다.

3000은 기초40%/응용60%의 선택된 평가 범위 수행 비율 100%이다. 전체 메이트 능력 최고치, 교정된 Elo, 문항별 난이도 보정 추정이 아니다. 필수46/48·분야4/6·추가상한 종료도 전체 완료와 다르다. 운영 캡처의 원본 픽셀은 이 실행 환경에서 열람하지 않았으며 부모의 관찰 기록을 사용했다.

## 감사 재개에 필요한 최소 근거

승인된 읽기 전용 운영 DB 접근 또는 소유 계정에서 내보낸 관련 진단 결과/고정 기준선의 비밀 제거 사본이 필요하다. 필요한 필드는 보고서/문항 ID, 버전, FEN/원본 수순, 제출수·판정·엔진 근거, 도움/기출/첫 시도 표시, 분야/난도, 기준선 sources 및 제외 집계다. PIN, 인증 토큰, 다른 사용자의 기록은 필요하지 않다. 이 누락은 다른 기능 구현·로컬 검증의 차단 요인이 아니다.

예시(실제 TEST3 기록 아님): 한 분야에서 기초4/응용4가 모두 유효 관찰일 때, 기초 1오답이면 `1 + round(2999 × (0.4×3/4 + 0.6×4/4)) = 2700`, 응용 1오답이면 `1 + round(2999 × (0.4×4/4 + 0.6×3/4)) = 2550`이다. 모두 완주한 선택 관찰은 3000이다. 어느 문항이 이 분모에 포함됐는지를 확인하지 않고 화면 점수만으로 채점 오류를 단정할 수 없다.
