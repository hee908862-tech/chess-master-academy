# 대체 수·부분 수행·문항 구조 감사

## 새 응답 정책: goal-alternatives-v1

새 세션만 사용한다. 기존 진행 세션에 정책을 소급 추가하지 않는다. 원본 item.line, 원래 expected, 과거 점수는 보존하고, 검증된 대체 실행 경로는 session.answer_line과 alternative_evidence에 별도 저장한다. 결과·snapshot에 정책을 기록하며 이전 정책(reference-line-v1)과 성장 그래프/레이더 비교를 분리한다. 수치 산식 skill-index-v1은 바꾸지 않았다.

| 과제 목표 | 이번 지원 범위 | 보류하는 범위 |
| --- | --- | --- |
| 원래 N수 이내 메이트 | 남은 내 수 3회 이하: 후보 수 뒤 모든 합법 방어에 대해 제한 수 내 메이트가 존재하는지 규칙 탐색. 증명한 가장 긴 방어의 수순을 사용자가 이어 둔다. 다른 후보 수를 선택하면 다시 검증. 더 빠른 메이트도 허용. | 6000노드/150ms 초과, 긴 메이트, 원본 종료 메이트/태그 불일치. 보류를 오답으로 바꾸지 않음. |
| N수 메이트 대신 더 긴 승리 | 모든 가지 검사 완료 시 원래 남은 수 내 메이트 불가능을 verified_non_mate로 관찰 | 장기 승리를 원래 목표의 만점으로 바꾸지 않음 |
| 유리함 유지·기물 획득·무승부·기타 수순 | 기존 실제 엔진 전후 비교와 관찰 근거 보존 | 비슷한 CP만으로 목표 달성·동등 정답으로 승격하지 않음. 정확한 종료 목표·루브릭이 없는 은행 자료는 equivalent_alternative 또는 unverified_alternative로 보류. |

이는 무제한 엔진 승부나 모든 과제의 대체 정답 지원이 아니다. 원본 FEN에서 시작하는 단일 국면 과제이므로 그 이전의 반복 국면 이력은 증명 대상이 아니다. 짧은 메이트만 모든 합법 방어를 검사하며 엔진 탐색 깊이로 증명을 꾸미지 않는다. 검증은 저장 트랜잭션 밖에서 하고 revision/세션을 재검사한다. 제한 예산 소진 시 후보가 틀렸다는 주장을 하지 않는다. 후보 수/최선 응수는 진단 제출 전에 노출하지 않는다.

부분 수행은 execution-observation-v1에 확인된 첫 수, 확인된 내 수 개수, 원래 요구 수, 목표 완료 여부, 중단 결과를 기록한다. 임의 0.5점 또는 ‘절반 실력’으로 환산하지 않는다. 새 수치 부분점수는 미구현이며 기존 점수에 조용히 섞지 않는다. 약한 AI의 실수로 끝난 승리와도 구분한다.

## 3000점의 일반적 원인과 감사 한계

이 문서는 TEST3의 실제 이력을 읽었다는 증거가 아니다. 현재 초기 모델은 분야별 기초/응용의 유효 관찰 각각 4개를 선택하고, 선택한 8개가 모두 완주이면 3000이다. 건너뛰기·부분 수행·미검증 대안·기출·도움은 유효 관찰 밖이므로 사용자가 기억하는 실패/중단과 분야 3000이 공존할 수 있다. 검증된 오답과 verified_non_mate는 유효 관찰이며 점수 기여는 0이다. 따라서 실제 오류 여부는 사용자 원문항, 당시 판정/도움/버전, 선택된 source를 연결해 확인해야 한다. 기록을 보지 않고 TEST3가 틀린 수를 정답 처리받았다고 단정하지 않는다.

## 실제 문제은행 구조 감사

재현: `python scripts/audit_diagnostic_diversity.py` (실제 배포 자료와 일치하는 journey-index.json.gz 필요). 산출: diagnostic-diversity-audit.json. corpus SHA256 241c7a902d7952b7a7501f383aaef4a4b7a189113b61c3b3c51e91d4881b7310, 600≤난도<1800 대상.

| --- | ---: | ---: | ---: |
| 메이트 | 4623 | 4807 | 8851 |
| 다중 수 계산 | 10449 | 13459 | 21601 |

| 승격 | 898 | 942 | 1612 |

구조 그룹은 구체 모티프 태그, 색별 기물 구성, 요구 내 수 깊이, 첫 이동 기물/포획/체크 특성이다. 이름이나 좌우 대칭을 독립 능력으로 세지 않는다. 이것은 교육적 독립성이 검증된 문항 수가 아니며 배치 관계를 완전히 표현하지 못하는 감사 지표다.

겹침은 설계상 크다. 계산/메이트 7746개, 계산/포획 10252개, 계산/방어 1551개가 같은 원문항이다. 다중 수 계산은 다른 분야의 수순 실행과 중첩되는 관찰이기 때문이다. 종반 전술의 같은 구조 최대 그룹은 44개이며 예시 2Qac8, 5XFTX, 5wQ7K. 방어의 최대 그룹은 27개(03mv2, 290Nj, 6J2Cp). 비슷한 구조가 종종 보이는 사용자 관찰은 가능하다.

현재 ID 및 시작·중간·종료 모든 국면 중복 차단은 유지한다. 하지만 서로 다른 국면의 유사 모티프까지 차단하지 않는다. 이번에는 난도별 출제 범위를 바꾸는 신규 구조 가중치를 임의 도입하지 않았다. 분야 명칭만 다른 문항을 체스 전 영역의 독립 진단이라고 주장하지 않는다. 일반 전략·오프닝·종반 전체는 여전히 미측정이며, 구조 다양성 개선은 문제 검토와 출제 분포 검증이 더 필요하다.

## 분기 국면 노출의 별도 보존

`POST /api/study/exposure`는 인증된 현재 소유자의 `branch_exposure_v1` 필드만 변경한다. 요청당 1–32개의 완전한 합법 FEN을 받으며 차례·캐슬링·합법 앙파상 권리는 보존하고 시계만 정규화해 같은 국면을 중복 저장하지 않는다. 원래 기보·답안·점수·완료 관찰은 수정하지 않는다. 서버 ProgressState의 필드별 비교/병합을 사용해 다른 진행 기록을 덮어쓰지 않으며 동시 동일 필드 충돌은 409로 재확인을 요구한다.

이후 새 진단·훈련에서는 분기에서 본 국면을 독립 미노출 후보에서 제외한다. 다른 탭의 아직 미응답 진단 문항도 제출 때 노출을 확인해 독립 관찰에서 제외하지만, 이미 제출 확정한 문항의 복기를 이유로 과거 관찰을 소급 무효화하지 않는다. 기존 학습 카드 재시작도 새 독립 노출로 세지 않는다. 노출은 오답이나 감점이 아니다.

계정당 최대 4096개 국면이며 한도 이후에는 기록을 조용히 잘라 미노출이라고 주장하지 않고 overflow를 보존한다. 이후 독립 여부를 확인할 수 없는 진단/훈련 근거는 보류하되 과거 점수는 유지한다. 사용자는 연습을 계속할 수 있다. 비로그인 상태에서는 정체성을 자동 만들지 않으며 브라우저의 미동기 노출을 명시적 계정 시작 후 동기화하는 클라이언트 흐름과 결합한다.
