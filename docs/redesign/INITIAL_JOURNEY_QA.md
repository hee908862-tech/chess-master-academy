## 검사 범위

- 백엔드: 초기 관찰/고정점수 분모/기출·도움·미확정 제외, 활성 세션 및 과거 기록 보존, 리뷰 멱등성, 범위부족·문제고갈·중단, 이전 corpus, 성장게이트 보존, 게스트 연결 소유권, 규칙관찰, 실제 Stockfish 대국 분석, Docker COPY 런타임 및 자산 패키징.
- 실제 로컬 UI/API: 신규 게스트 초기48개 원본정답 착수→결과→맞춤훈련; 1366×768,1180×650,360×800,390×844,844×390 시작/홈/복귀/새로고침; 서버확정 진행률; 키보드/뒤로/회전/200%CSS확대; 중복시작/제어된503.
- UI 대역/실제 로컬 혼합: AI 관찰 응답은 명시적 API doubles, 지연/오류/계정변경/도움표시/두대국조회. 기존훈련충돌은 실제 격리DB 상태로 보존 확인.
- 이전 UI 회귀: 성장 차트, 게스트 브라우저 상태, 과거 근거 읽기 전용. 기존 테스트2건은 baseline main에서도 동일 실패 재현 후 PR41/42의 실제 기대 동작으로 갱신(비교근거부족 문구, 복기 읽기전용6개 버튼).
- 최초 자동48완주 실행은 180회/분 게스트 보호 제한에 걸렸다. 보안 규칙을 바꾸지 않고 추가 GET을 제거하고 조작 간격을 둬 통과했다. 운영부하시험은 하지 않았다.

최종 실행 수와 결과는 아래 확정 기록에 기입한다. 반복 실행 횟수는 검사 개수로 부풀리지 않는다.

## 운영 재검수 경로와 제한

1. 새 격리 게스트/기존 미완료 정체성에서 `#diagnosis/initial`: 잔여/분야 바로가기→풀이→저장하고홈→진단이어하기. 기존 QA 진행진단은 사용하지 않는다.
2. 이전 호환관찰이 있으면 그 수만큼 부족분이 줄어드는지 확인. 건너뛰기는 근거완료로 바뀌지 않아야 한다. 기존 성장 재진단과 별개로 초기 보충 가능.
3. 완료/보류 결과에서 결과확인→맞춤훈련, 기존훈련이 있으면 충돌안내/이어하기. 첫 결과를 체스전체 숙련·성장확정으로 해석하지 않는다.
4. 완료된 테스트대국의 내정보 ‘대국 지표’ 또는 대국후 ‘실전 장면’: 규칙관찰, 도움/미측정/출처, 원위치/실제수후, 관련훈련. 기준선점수 불변.
5. 운영 API지연/복기평가 성공은 별도 확인. 로컬통과가 이를 해결했다는 뜻은 아니다.

이 실행 환경의 운영 접속은 기존 CONNECT 프록시403 차단 이력이 있어 재시도/우회하지 않았다. 부모의 별도 허용 브라우저 운영검수 대기. 실제 모바일기기·실제초보자 관찰은 미실시. Chromium viewport/CSS확대는 이를 대신하지 않는다. Docker검사는 COPY payload/index 생성/import이며 로컬 Docker image build/실제PostgreSQL 검증은 아니다. 기존 Render 자동배포의 실제 빌드·Live는 배포기록으로 별도 확인한다.
