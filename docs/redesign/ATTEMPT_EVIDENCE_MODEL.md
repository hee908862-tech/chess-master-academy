# 원래 시도 전체의 수행 근거 모델

`attempt_evidence.py`는 저장된 보고서 목록을 입력받는 순수 함수 모듈이다. 데이터베이스, 계정, 저장 API에 접근하지 않으며 기존 점수나 답안을 변경하지 않는다. 보고서는 원래 배정 순서대로 오래된 것부터 전달한다. 새 1~3000 산식, Elo, 난이도 보정 능력, 신뢰구간을 도입하지 않는다.

## 전체 분모와 불확실성

`summarize_attempts(reports, corrections=None, corpus=None)`는 유효 관찰 슬롯만 추리는 대신 모든 원래 배정을 행으로 보존한다. 미응답, 중단, 엔진 실패, 검증되지 않은 대안도 첫 미노출 시도의 분모에서 사라지지 않는다. 검증된 오답은 관찰이며 성공에는 포함되지 않는다. 도움·기출·반복은 별도 분류로 남고, 동일 원문항 또는 수순 국면의 나중 시도가 앞선 미확정을 성공으로 대체하지 않는다.

원래 시도 수를 N, 완료를 S, 검증된 오답을 W, 명시적으로 중단·건너뛴 미완료를 F, 판정 미확정을 U, 아직 응답 기록이 없는 배정을 P라고 하면 N=S+W+F+U+P다. `completion_ratio=S/N`, `logical_bounds=[S/N,(S+U+P)/N]`다. 명시 미완료는 원래 시도에서 완료하지 않았다는 관찰이므로 경계 상단에도 성공 가능분으로 넣지 않는다. 그러나 이를 오답이나 능력 0으로 취급하지 않는다. 미완료/건너뜀/부분 수행/미응답 배정은 별도 수로 표시한다. 이는 미확정 결과가 모두 실패하거나 모두 성공으로 밝혀질 때 가능한 논리적 경계이며 통계적 신뢰구간이 아니다. 예를 들어 성공 8개와 미확정 2개는 관찰 완료율 80%, 가능한 경계 80–100%이며 확정 100%라고 표시하지 않는다. N=0이면 비율과 경계는 null이다.

미노출·첫 시도·도움 여부 또는 독립성을 입증하지 못한 원래 시도도 조용히 제거하지 않는다. `eligibility_unknown` 및 사유를 별도로 보존한다. 모든 저장 결과가 성공이라도 이러한 불확실성이 남으면 `confirmed_ratio=null`, `independence_confirmed=false`다. 관찰 수행율이 100%인 것과 독립 평가가 확인된 것은 다르다.

기초/응용의 유효 관찰만 선택한 기존 수행 점수는 그대로 둔다. 이 모듈은 기존 점수 옆에서 분모와 제외 근거를 설명하는 별도 버전 `original-attempt-evidence-v1`이며, 이전 점수를 소급 대체하지 않는다. 서로 다른 평가 범위·자료·답안 정책 또는 교정 투영은 비교 가능한 성장이라고 연결하지 않는다.

## 수순 실행과 난도

`execution_observation`은 저장된 확인 내 수/원래 요구 내 수의 비율을 제공한다. 조기 메이트로 목표를 달성했어도 원래 긴 수순의 실행 비율과 목표 완료는 다를 수 있다. 이 비율은 부분 능력이나 임의 반점이 아니다.

복원 가능한 각 착수 국면에서 합법 수가 정확히 하나면 강제 이동, 둘 이상이면 선택 가능한 이동으로 구분한다. 이것은 가장 중요한 결정, 전술 난도, 핵심 기술을 추정한 값이 아니다. 원래 수순과 다른 오래된 분기의 누락된 상대 수를 추측해 복원하지 않는다. 저장 FEN도 없고 원본 접두 수순으로 복원할 수 없으면 `unreconstructed_submissions`로 표시한다.

외부 문제은행 rating의 실제 값, 최소·최대, 배정 band를 보존한다. 한 구간 내부의 난도 차이를 능력 점수로 보정하거나 통계적으로 검증된 정밀도라고 주장하지 않는다.

## 제한된 원문항 재검증

`resolve_attempt(item, report_policy=None, max_nodes=6000, seconds=.15)`는 새로운 교정 제안만 만든다. 원문항 전체 JSON의 SHA256 `item_fingerprint`로 제안을 특정 원본에 묶는다. 원래 FEN·원본 합법 수순·실제 제출 수·저장 response FEN과 expected를 대조하고, 최초 불일치 이전이 원본 수순과 동일할 때만 다음 국면을 복원한다. 오래된 대체 분기를 추측하지 않는다.

지원 범위는 PR45의 `goal-alternatives-v1` 규칙 증명과 같다. 원래 종료가 메이트이며 남은 내 수가 3회 이하인 경우 모든 합법 방어에 대해 원래 수 제한 내 메이트를 확인한다. 6000노드/150ms 한도 초과, 지원하지 않는 목표·정책, 불완전 원본은 판단 보류다. 유리함 유지·기물 획득·장기 승리·무승부를 메이트와 같은 기준으로 판정하지 않는다.

- 원래 N수 안에 메이트할 수 없음을 완전 탐색으로 확인: `verified_non_mate` 교정 제안.
- 후보가 목표를 달성할 수 있지만 뒤의 사용자 수순이 아직 실행되지 않음: `verified_goal`, `full_completion=false`, `final_verified=false`. 전체 정답으로 바꾸지 않는다.
- 실제로 제출한 수 자체가 즉시 체크메이트임을 확인: 완료 교정 제안 가능.

`corrections`는 append-only 기록의 읽기 투영이다. report/item/fingerprint 및 제안 버전이 모두 일치하고 최종 검증된 제안만 effective outcome에 반영한다. 원본 outcome과 기존 점수는 그대로 노출한다. 다른 문항, 다른 보고서, 바뀐 원본, 미실행 후속 수의 긍정 증명은 교정 완료로 합산하지 않는다. DB 저장·승인·소유권·재검증 경로는 이 순수 모듈의 호출자가 담당한다.

## 활동 시간의 별도 관찰

행의 `timing`은 `diagnosis_timing.public_timing` 결과이며 브라우저가 보고한 미신뢰 활동 시간이다. 과거 측정이 없으면 null이고, 서버 표시 시각 차이로 생각 시간을 만들어 내지 않는다. `elapsed_ms`는 관측된 양의 active_ms만 사용하며 flags·availability·trusted=false를 함께 전달한다.

시간 추세는 도움·반복·독립 여부 불명·교정 투영을 제외한 정확한 완료 관찰만 이용한다. 분야·외부 난도 정확한 값·정렬한 주제 태그·답안 정책·수순 길이·평가 방식·점수 버전뿐 아니라 corpus와 진단 버전도 나눠 계산한다. 외부 난도나 주제가 없으면 비교하지 않는다. 같은 외부 난도도 실제 난도가 같다는 보장은 아니다. 동일 조건 3개부터 참고 중앙값, 앞뒤 각각 3개부터 기술적 비교를 제공한다. 시간은 점수에 합산하지 않으며 빨라졌다는 결과를 능력 향상의 인과 근거로 해석하지 않는다.
