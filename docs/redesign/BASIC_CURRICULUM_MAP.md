# 체스 기본 교육 목표 대응

2026-10-23에 Lichess 공식 [단원 목록](https://github.com/lichess-org/lila/blob/master/ui/learn/src/stage/list.ts)과 아래 18개 단원 파일을 직접 읽었다. 원본은 18단원·110실습이다. 우리 구성은 같은 기본 주제를 짧은 보드 행동으로 다루는 **18단원·62실습**이다. 실습 수, 경로 최적화 게임, 반복 난도, 학습 효과가 같다는 뜻은 아니다.

원본의 문구·그림·FEN·구현 코드는 복제하지 않았다. 아래 참조는 교육 목표의 인벤토리다. 새 국면은 `basic_rules_content.position()`의 자체 기물 배치로 만들었고, 표준 초기 배치는 공통 체스 규칙으로 생성했다. 기존 자체 `foundation_content.py` 과정과 개인 기록도 바꾸지 않았다.

## 공통 행동·판정 계약

- `move`: 표준 UCI 이동. `python-chess`의 실제 합법성 검사 후 목표 predicate를 확인한다. 메이트·스테일메이트·캐슬링·앙파상은 실제 보드 상태와 권리로 판정한다.
- `square`: `square:e4`처럼 보드의 칸을 선택한다. 보기 버튼을 누르는 이해 확인과 직접 이동은 서로 다른 행동으로 기록한다.
- `place`: `place:Q:d1`처럼 말과 칸을 지정한다. 초기 배치의 일치 여부만 검사한다. 킹 없는 중간 배치에 일반 대국 합법성을 적용하지 않는다.
- 일반 목표의 합법 대안은 모두 인정한다. 지정한 한 수와 문자열이 다르다는 이유만으로 실패 처리하지 않는다. 목표가 다른 합법 수는 실제 이동 후 배치를 남기고 이번 목표 미충족으로 설명한다.
- 예시 응수가 있는 단원은 실제 합법성을 확인한다. 첫 사용자 수가 목표를 충족하지 않았다면 상대가 두지 않은 응수를 표시하지 않는다.
- 완료와 목표 미충족은 구별한다. 일반 단위 성공은 서버 저장 확인 뒤 짧은 피드백과 함께 다음 단위로 이어지고, 목표 미충족과 스테일메이트 결과 확인은 명시적인 다시 하기·다음 조작을 유지한다. 기존 계정·답안·점수·기초 진도는 새 단원의 성공으로 수정하거나 소급 인증하지 않는다.
- 서버 API는 `example_actions`를 공개하지 않는다. 클라이언트와 서버는 동일 predicate를 구현하되 서버가 원래 배치부터 전체 행동을 검증한다.

## 콘텐츠 검사 근거와 남은 검증

`validate_content()`로 자체 규칙 실습 45개의 예시 완료와 18개 원본 주제 참조를 확인했다. 배치 실습 하나를 제외한 모든 규칙 시작 국면은 정상 체스 FEN이다. 배치 실습의 완성 결과는 표준 초기 배치와 일치한다. 상대 사전 시연과 후속 응수도 합법 수로 검증한다.

추가 로컬 전수 확인에서 한 수 규칙 실습의 성공 가능한 합법 대안 79개가 각각 완료됐고, 승격 후 이동은 퀸·룩·비숍·나이트 네 선택 모두 완료됐다. 캐슬링 권리 또는 앙파상 권리를 제거하면 해당 특별 수를 성공으로 인정하지 않는 것도 확인했다. 이 숫자는 해당 순수 콘텐츠 검사의 범위이며 실제 앱 저장·모바일·운영 검증 수와 합산해 사람의 학습 효과로 표현하지 않는다.

실제 초보자의 새 흐름 재참여·성취 검증은 하지 않았다. 원본 110문제의 난도·반복량 또는 학습 효과와 동등하다는 주장도 하지 않는다. 앱 통합 후 로컬 브라우저·저장·계정 분리·운영 검수는 별도 QA 근거가 필요하다.


## 세부 행동 목표 감사

단원 이름만 있는지 확인하는 데 그치지 않고, 다음 개념이 실제 보드 행동과 판정으로 연결되는지 점검했다. 실패한 목표는 반복 입력으로 성공 처리하지 않으며 새 확인에서 다시 시도한다.

| 세부 개념 | 직접 행동과 판정 근거 | 구분·한계 |
|---|---|---|
| 여러 기물의 활용·협력 | `two-rooks-left/right`에서 서로 다른 룩 선택, `two-bishops-light/dark`에서 서로 다른 비숍 선택, `pawn-choice`에서 목적지에 맞는 폰 선택, `protect-piece`에서 다른 말의 재포획 준비, 메이트 씬에서 킹과 공격 말의 협력 | 복잡한 여러 기물 최단 경로 게임과 동등하지 않다. |
| 비숍의 색 제약 | 두 비숍이 놓인 같은 배치에서 g5와 b5 목표에 각각 다른 비숍으로 이동 | 한 비숍이 반대 색으로 가는 수는 합법수 검사에서 거절한다. |
| 나이트의 뛰어넘기 | `knight-jump`의 중간 내 폰을 넘는 L자 이동 | 내 말이 있는 도착 칸은 여전히 금지한다. |
| 폰 전진과 잡기 구분 | `pawn-forward/capture`, `capture-pawn`, `pawn-blocked-front`: 빈 앞칸 전진과 대각선 포획을 각각 직접 수행 | 앞의 상대 폰을 정면으로 잡는 수도 거절한다. |
| 체크 회피 세 방법 | `escape-king`, `escape-block`, `escape-capture`의 이동·가로막기·잡기 | `escape-knight`는 나이트 체크에 가로막기 대안이 없음을 별도 확인한다. |

| 캐슬링: 도착 칸 공격 | `castle-destination-attacked`에서 공격받는 g1을 선택 | e1/f1은 안전하며 실제 캐슬링 합법 수가 없다. |
| 캐슬링: 킹의 이동 이력 | `castle-right-lost`에서 권리 없는 국면의 킹 한 칸 이동 | 킹이 돌아왔다는 설명과 FEN 권리 부재를 함께 제시하며 현재 배치만으로 이력을 추측하지 않는다. |
| 캐슬링: 룩의 이동 이력 | `castle-rook-right-lost`에서 움직였던 오른쪽 룩 대신 권리 남은 왼쪽 룩과 실제 캐슬링 | FEN의 Q 권리로 e1c1만 허용하고 e1g1은 불가다. |
| 캐슬링: 막힌 길 | `castle-blocked`에서 막는 나이트 선택, `castle-prepare`에서 직접 나이트를 옮긴 뒤 다음 내 차례에 캐슬링 | 확인 행동과 실제 길을 비우는 행동을 모두 제공한다. |
| 앙파상 즉시성·줄·새 기회 | `ep-now`, `ep-expired`, `ep-rank`, `ep-repeat`의 사전 상대 이동·현재 권리·다른 줄·새 기회마다 포획 | 배치가 같아도 EP 권리가 없으면 특별 포획을 인정하지 않는다. |
| 스테일메이트와 메이트 | 같은 원래 배치에서 `make-stalemate`와 `avoid-stalemate`의 서로 다른 합법 수를 직접 수행 | `is_stalemate()`와 `is_checkmate()`로 판정하며 완료 후 다음 행동은 사용자가 선택한다. |
| 기물 가치보다 합법성 우선 | `value-legal-first`: 나이트 잡기는 내 킹을 퀸 공격에 노출하여 불법, 퀸 잡기는 합법 | 숫자가 높은 상대 말이 보인다는 이유만으로 합법성 검사를 생략하지 않는다. |

이 감사에서 발견한 캐슬링 세 가지 세부 조건과 막힌 폰의 전진/잡기 구분을 기존 predicate의 새 국면 네 개로 보완했다. 새로운 채점 정책이나 고급 전술 기능은 추가하지 않았다.
