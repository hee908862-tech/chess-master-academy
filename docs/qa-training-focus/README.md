# 훈련 PC 판정·핵심 조작 배치 후속

기준 main `335311263840ea6a089371e9c2c37c8ba3f2d7b4` (PR30). 같은 실행 환경의 새 /tmp 작업트리에서 기존 변경/자료를 보존했다. 운영 계정/기보/API는 사용하지 않았다.

## 재현과 최소 수정

정상 Chromium, 임시 로컬 계정의 실제 저장 훈련을 새로고침 후 복원했다. 수정 전1180×757: 보드y264.17–751.17, 판정y765.17–835.17, 핵심 조작y841.17–887.56. 운영과 동일하게 판정과 조작이 첫viewport 밖이었다. before JSON/이미지/실패로그를 보존한다.

변경은 `public/focus-layout.js`, `public/focus-layout.css`의 표시 배치만이다. 기존 판정/저장 상태, controls, 메시지/목표/연결/도움 정책 노드를 오른쪽 학습패널 첫 영역으로 옮겼다. 컨트롤러/클릭 핸들러/DOM ID/데이터/채점/도움 규칙은 그대로다. 모바일에서는 같은 영역이 보드 바로 다음이다. 기존 경로/개념/해설/기록을 삭제하지 않는다. 컨테이너 실제 폭이700px 이하이면1열로 전환해200% 확대에서 보드가 작아지는 것을 막는다.

PC1180×757: 보드는 기존487px 그대로, 판정y207.17–277.17, 조작y285.17–331.56. PC1280×720: 보드450px, 판정/조작은 같은 옆 열. 모바일은 글자·44px버튼·보드를 줄이지 않고 세로간격10px만 회수했다. 긴 문장/확대에서는 문서 스크롤을 허용한다.

## 검사

- 수정 전 명확한 재현1실패(기대 실패).
- 첫 수정4통과/1실패:200% 확대에서 기존2열이 보드를202px로 줄임. 컨테이너1열 보완 후 동일5건 전부 통과.
- 최종은 모바일에서도 보드·판정·핵심 조작이viewport내 있는지 assertion을 강화한 관련 회귀 실행 중. 결과는 종료 후 갱신한다.
- 새 검사는1180×757,1280×720,390×844,320×844,1280×720의CSS200% 확대, 가로넘침/기물크기/44px조작/요소가림/키보드포커스, 선택패널 왕복의쓰기0와active동일성을 확인한다. 기존 실제API 검사로 지연/완료/오류/재시도/도움/승격/계정전환을 함께 검사한다.
- 구문 및 COPY/import/static 패키징도 확인한다. 이전PR30의672통과는 이번 코드의 전체 결과로 집계하지 않는다.

물리 모바일/운영QA/실제Docker·PG는 이번 검사에 포함하지 않는다. 루트 디스크0, /tmp약7.8GiB. 실제자료/DB삭제나병합/배포없음. JSON에는화면좌표만 저장하고계정식별정보를넣지않는다.
