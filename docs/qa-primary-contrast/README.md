# 공통 primary 버튼 대비

기준 main `c076355b95970d31bc66023acba070f70ab75d5d`. 최종 앱/테스트 소스 `6d2341d8b26326ac96de4f40aef4cb4a629a5d73`. 동일 환경의 별도 `/tmp/cma-primary-contrast` 작업 트리이며 이전 미커밋 자료를 보존했다.

## 재현과 수정

최신 main 실제 Chromium의 대국 시작 버튼은 흰 글자와 #769aff→#8daaff 그라데이션으로 대비가 2.67975:1 / 2.25166:1이었다. baseline.log의 의도된 실패로 재현했다. 공통 `.btn.primary` 글자색만 #111827로 바꾸고 PR21의 홈 전용 중복 규칙을 제거했다. 배경/기물/보드 테마/폰트/비활성 규칙/인증/저장/대국 JS는 변경하지 않았다. 스타일 소스 검색상 다른 primary 색 재정의는 없었다.

홈·대국·진단·훈련의 실제 computed style을 320×800 / 1280×720에서 검사했다. 정상 및 hover의 그라데이션 양 끝 대비는 모두 6.61991:1 / 7.87849:1이다. 기초의 권장 시작은 일반 btn이므로 공통 primary 변경의 직접 대상이 아니며 키보드 포커스·폭·저장 대기/오류 안내 보존을 검사했다.

## 수행 결과

- 관련 4개 파일 첫 실행: 32 통과 / 신규 검사 1 실패. 실패는 비활성 전환 0.15초 전에 opacity를 읽은 테스트 동기화 문제였다. 앱을 바꾸지 않고 테스트에서 실제 전환 완료를 기다리게 했다. final.log 보존.
- 최종 소스에서 신규 대비/키보드/좁은 화면/기초 대기·오류/비활성 검사 3/3 통과(focused.log). 기존 32건 중 2건과 중복이므로 합산하지 않는다.
- 기존 첫 방문·대국·기초 회귀는 동일 최종 앱 스타일에서 통과했다. 전체 회귀는 요청 범위에 맞춰 미실행이며 이전 528건을 이번 결과로 재사용하지 않는다.
- HTML parser / Python AST / git diff --check 통과. JS 변경 없음. Chromium이 실제 스타일을 읽은 값과 캡처를 보존했다.
- 키보드 포커스 outline 표시, 정상/hover 색, disabled의 기존 opacity .5 및 Tab 제외 유지. 비활성 버튼은 대비 적합성을 주장하지 않는다. 대국 시작 전 힌트/무르기 비활성 이유와 기초 저장 대기/실패 안내를 확인했다.

PC 진단, 좁은 대국/기초 및 비활성 캡처의 픽셀을 직접 확인했다. 물리 모바일·운영·전 화면 접근성 인증은 미실행이다. 저장소 전체의 모든 색/텍스트 대비가 해결됐다는 뜻이 아니다. 루트 여유0, /tmp 약8GiB로 Docker/PG는 재실행하지 않았다. 운영 QA 미완료 대국이나 계정에 접근하지 않았고 병합·배포하지 않는다.
