# 완전 초보의 첫 룩 수업과 기초 설명

기준 main: PR47 `496d0f85c52aa2fe9673e6978f9e06a6a18db4ee`.

## 관찰과 적용 범위

한 초보자의 실제 피드백에서 말의 이름과 모양, 이동 이유를 연결하기 어렵다는 문제가 제기됐다. 이것은 한 사람의 관찰이며 모든 초보자에게 일반화하거나 이전 과정 도달을 이해의 증거로 해석하지 않는다. 원본 이미지의 지원 다운로드는 이 실행 환경에서 `library file transfer failed: download failed`로 실패했다. 전달받은 관찰을 근거로 구현했으며 원본 픽셀 대조는 하지 않았다. 개인 대화 이미지·이름·계정 기록은 저장소에 포함하지 않는다.

[Chess.com 공식 입문 과정](https://www.chess.com/lessons/learn-to-play-chess)은 기물별 이동, 잡기, 체크, 특별 규칙을 작은 수업과 과제로 나눈다. [Lichess 공식 입문 소스](https://raw.githubusercontent.com/lichess-org/lila/master/ui/learn/src/stage/list.ts)는 기물 단원과 잡기·보호·체크, 특별 규칙을 구분한다. 이 구분을 참고해 말 그림·이름을 현재 한 가지 규칙과 연결했다. 외형·공식 문구·그림을 복제하지 않았다. 시범→안내 연습→목적지 안내 없는 확인→새 배치 확인은 이번 앱의 설계이며 두 사이트가 이 정확한 순서의 효과를 검증했다고 주장하지 않는다.

## 첫 수업

새 이용자의 기초 시작은 `rook-first-v1`이라는 별도 입문으로 연결한다.

1. 큰 실제 테마 룩 그림과 이름을 보고 보드에서 같은 밝은색 말을 찾는다. 게임 목적과 내 말/상대 말을 짧게 소개한다.
2. 가로 이동을 본다. 다시 재생할 수 있고 시청 확인은 수행 성공과 다르다.
3. 세로 이동을 본다. reduced-motion에서는 긴 이동 효과를 생략한다.
4. 표시된 목적지로 직접 이동한다. 안내 연습으로 기록한다.
5. 목적지 화살표·가능 칸 표시 없이 룩의 합법적인 이동을 직접 고른다.
6. 룩 위치가 바뀌고 내 폰이 길을 막는 배치에서 다시 고른다. 해당 룩의 모든 합법 수를 인정하고 실제 둔 수로 보드를 복원한다.

인식·시청·안내·첫 시도 확인·피드백 후 재시도는 별도 결과다. 불법 이동은 이유를 알려주고 판을 유지한다. 이미 알려준 규칙을 적용하는 확인이지, 도움을 전혀 받은 적 없는 능력 측정이 아니다. 이 두 배치 성공도 숙련 인증·레이팅·진단·훈련 크레딧이 아니다. 시간제한이나 점수 경쟁은 없다. API의 시청 확인은 사용자의 확인 조작 기록이며 실제로 눈으로 보았음을 서버가 증명하지 않는다.

## 기존 과정 전체

기존 10개 과정·26개 실습의 FEN/수순/판정/단계 순서는 유지한다. `beginner_content.OVERLAYS`의 표시 설명은 각 실습의 말 그림·이름, 선수 개념, 지금 필요한 규칙, 행동을 보드 앞에 노출한다.

- 룩/비숍, 나이트/퀸: 묶음 안에서도 현재 말 하나의 모양·이름·이동 방향부터 소개한다.
- 폰: 한 칸 전진을 먼저 설명하고 첫 두 칸과 대각선 잡기를 구별한다.
- 킹/체크: 지켜야 하는 말, 안전한 한 칸, 공격받음, 피하기·막기·잡기의 이유를 분리한다.
- 메이트/스테일메이트: 체크 여부와 가능한 수 여부를 구별하며 기존 설명형 판단 문제를 독립 진단으로 포장하지 않는다.
- 캐슬링/승격/앙파상: 필요한 두 기물·안전한 길·끝줄·즉시 다음 수 조건부터 설명한다. 기존 승격 선택과 실제 상대 폰 시연을 보존한다.
- 보호/가치: 숫자 암기보다 보호 관계를 먼저 설명한다.
- 실제 차례: 내 색과 번갈아 두기, 중앙·전개·킹 안전을 오프닝과 연결한다. 지정 예시 암기를 유일한 정답으로 주장하지 않는다.

기본 이유는 결과의 다음 행동 앞에 항상 보인다. 보충 원문·시각 범례·목록 착수·분기 탐색은 찾을 수 있는 상세 영역에 유지한다. 정상 저장은 작은 글씨로, 오류와 재시도는 명확하게 표시한다. 전체 목록은 신규에게 자동으로 펼치지 않으며 이미 아는 이용자의 명시적 자유 선택·완료자 복습은 보존한다.

## 기록과 버전

`foundation_v1.courses['rook-first-v1']`만 추가하며 기존 10개 완료 분모에 넣지 않는다. 새 기록에 `beginner-understanding-v1`, 안정적인 step_id, run, attempts, 실제 move, 결과 종류를 저장한다. 기존 숫자 index/ply/completed_steps를 재배치하지 않는다. 이후 이 입문의 단계 순서를 바꾸려면 이 ID를 그대로 보존하고 새 버전을 만들어야 한다.

기존 시작한 과정이 있으면 새 입문을 강제 추천하지 않는다. 선택적으로 새 확인을 시작했다 돌아와도 기존 진행은 그대로다. 복습은 이전 checks를 지우지 않고 새 run으로 구분한다. GET/시범 재생은 진행을 생성하지 않는다. 기존 인증·소유권·revision/CAS 저장을 사용하며 게스트 연결 보호를 변경하지 않는다. 기존 진단 시간·점수(PR47), 기보, 계정, 훈련 세션은 수정하지 않는다.

## 운영 재검수 경로

기존 QA 기록을 건드리지 않는 별도 허용 정체성에서 홈 → 기초부터 배우기 → 룩 찾기 → 가로/세로 시범 → 안내 → 독립 → 새 배치를 확인한다. 결과의 시범/안내/첫 확인 구분, 홈·새로고침 복원, 전체 과정 선택과 기존 완료자 복습을 본다. 기존 계정은 읽기 조회로 원래 진도와 새 확인 미실시가 함께 보이는지 확인할 수 있다. 새 계정 생성·학습 쓰기는 검수자가 승인된 격리 경로에서만 수행한다.

실제 초보자 재참여·사람 행동 관찰은 하지 않았다. UI·자동검사·개발자의 직접 조작은 학습 효과의 실증 검증이 아니다. 모바일 검사는 Chromium 에뮬레이션이며 실기기가 아니다. 운영 사이트 접속 프록시 차단을 반복하거나 우회하지 않는다.

## 검사 근거와 발견한 회귀

- 백엔드·기록 보존·콘텐츠·패키징: 20개. 새 입문의 모든 합법 룩 대안, 실제 선택 수의 GET 복원, 불법/다른 말 선택, 피드백 후 성공, 복습 이력, 중복·동시 CAS, 계정 분리, 이전 활성 수순과 완료10/10, 다른 상태 무변경을 확인했다. Docker COPY만으로 서버·콘텐츠가 포함되고 import 가능한지 검사했다. 로컬 Docker 이미지 빌드는 하지 않았다.
- 새 실제 로컬 Chromium/API 흐름: 7개. PC1366×768, 모바일360×800/390×844, 가로844×390, 키보드, reduced-motion, 200%확대, 저장 실패, 새로고침, 홈 복귀, 별도 계정 분리, 기존 완료자의 선택 새 확인을 포함한다.
- 관련 과정 전수 조작: 2개. PC1366×540와 모바일390×844에서 기존26개 실습을 모두 실제 버튼/보드/승격 선택으로 완료하고 행동 전 설명 및 결과 이유의 가시성을 확인했다.
- 새 시범의 공통 착수음: 1개. 식별에는 소리 호출0, 한 번 시범에는1, 다시 보기에도 추가1회만 발생했다. 브라우저 호출 검사이며 실제 스피커 청취 검사는 아니다.
- 관련 회귀 선택: 61개. 기초17개, 분기 탐색, 착수음·복기, PR47 점수 저장, 게스트 연결 보안, 홈의 신규/진행/완료/복습 경로를 포함한다. 실패를 숨기지 않았다. 첫 실행은53통과8실패였고, 제품 회귀와 테스트 절차를 구분해 수정했다.

실제 수정한 회귀는 정답 후 안내 높이가 줄어 모바일 보드가22.5px 이동한 것, 앙파상 재생 중 읽기 전용 안내 누락, 메이트/스테일메이트 범례 누락이다. 같은 단계/너비의 안내 높이를 보존하고 사실 설명을 복원했다. 별도 검토에서 흑 시점 킹 그림도 흑으로 표시하며 결과 후 내 색이 바뀌지 않게 수정했다. 기초17개 재검사는16통과1실패였고 마지막 실패는 오류 발생 전 보드 아래 칸을 클릭할 때 Playwright가 자동으로9px 스크롤한 것이었다. 실제 오류 전후 좌표는 같았다. 따라서 클릭 후·POST 전 위치를 기준으로 잡고 오류 후2px 미만 검사 기준은 유지했다. 닫힌 전체 목록은 테스트에서도 명시적으로 열도록 진입 절차를 갱신했다.

테스트 환경 재연결 후 임시 Python 의존성을 다시 설치했다. Stockfish 실행 파일은 남아 있지 않았고 공식 릴리스 조회의 로컬 다운로드 준비가 `Tunnel connection failed: 403 Forbidden`으로 차단되어 중단했다. 실제 엔진은 이번에 재실행하지 않았다. 합법 수와 체크/특별 규칙은 python-chess로 검사했고 기존 엔진 관련 화면/저장 회귀는 명시적 테스트 대역 또는 엔진 없이 동작하는 범위다. 운영 원본 계정·기록에 쓰기는 하지 않았다.

최종 수정 뒤 새 브라우저7개와 남은 오류 fixture1개를 함께 재실행해8개 모두 통과했다. 앞서 통과한 관련 검사와 합쳐 고유91개 검사에 통과 근거가 확보됐다. 단일 실행91개라고 주장하지 않으며 위의 최초 실패와 재실행을 구분한다.
