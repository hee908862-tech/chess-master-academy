# 대국 집중 레이아웃 — 검증 범위

기준 main: `edd94e0b1c78f2a17d6bec5bbba2807f92985925`. 대국 화면과 화면 전환의 스크롤/포커스만 변경한다. 첫 방문 체험/로그인/홈 개편은 별도 단계다.

## 변경 및 보존

- 기존 보드와 버튼 DOM을 이동한다. 새 게임/착수/AI/힌트/무르기/시계 API 및 서버 코드는 변경하지 않는다.
- 진행 중 설정은 접고, 차례·시계와 보드를 먼저 배치한다. PC는 보드 옆, 모바일은 바로 아래에 힌트·무르기를 둔다. 비활성 상태도 위치와 이유를 유지한다.
- 프리무브 설정과 기권을 보조 도구로 구분한다. 예약/통신 상태는 접힌 영역 밖에서 읽을 수 있다. 대국 정보와 지표도 기존 내용을 보존한다.
- 대국 중 모바일 메뉴는 문서 흐름 안에 둬 보드/승격을 덮지 않는다. 계정/일반 안내 배너는 대국 집중 화면에서만 숨기고 사용 방법 버튼은 유지한다.
- 실제 다른 화면으로 이동할 때 화면 영역 포커스/상단 스크롤을 복원한다. 같은 대국 화면 선택, 메뉴 열기/닫기는 진행을 재시작하지 않는다.

## 수용 조건과 증거 구분

일반 화면은 CSS viewport 360×800 / 390×844 / 1280×720 / 1366×768에서 활성 대국의 보드 전체·차례·시계·힌트·무르기가 viewport 안에 들어오는지 경계 좌표로 검사한다. 핵심 버튼 높이 44px 이상. 짧은 1280×600, 가로 844×390, 320px 폭, 확대는 스크롤을 허용하고 주변 UI 가림/가로 넘침을 검사한다.

`tests/test_game_focus_browser.py`는 실제 로컬 SQLite 임시 계정/대국/Stockfish/힌트/무르기/흑 래피드/재접속과, 명시적으로 통제한 체크·AI 대기·통신 실패·종료·승격 상태를 구분한다. `tests/test_board_interaction.py`는 통제 응답으로 프리무브/취소/승격을 검증한다. 기존 도움 기록·기보 브라우저 검사는 실제 로컬 API를 쓴다. 물리 기기, 운영 사용자, 브라우저 자체 확대와 CSS 200% 확대는 동일한 검증이 아니다.

## 환경 제한

동일 환경 `/tmp`를 사용했다. 루트/Docker/기존 PostgreSQL 볼륨 파일시스템은 `df -h /` 기준 여유 0으로, 새 이미지 빌드 및 PostgreSQL 쓰기 검사는 실행하지 않는다. 기존 이미지/DB/로그/사용자 파일을 삭제하지 않았다. 과거 PR의 Docker/PG 통과를 이번 결과로 재사용하지 않는다.

참고 첨부 33907.jpg는 지원 Library materialize helper에서 `library file transfer failed: download failed` (exit 1)로 다운로드가 실패했다. 해당 원본 픽셀을 직접 보았다고 주장하지 않는다. 이 PR의 로컬 Chromium 캡처는 별도 직접 확인 자료다.

## 검사 이력

- 구현 초기: 새 검사 2건 실패(사용 안내 배너의 추가 높이, CSS 200% 확대 시 열 넘침). 배너는 대국에서만 숨기고 컨테이너 너비에 따른 한 열 전환으로 수정했다.
- 이후 실제 더보기 이동 검사에서 기존 `scrollIntoView`의 중복 스크롤과 비동기 제목 교체 뒤 포커스 소실을 발견했다. 화면 전환을 공통 경로에 모으고 안정적인 화면 영역에 포커스를 둔다.
- `645909c` 전체 검사 시도는 후속 Escape 보완 때문에 중단했다(29+40 통과, exit 2). **전체 통과가 아니다.**
- `cc5038c` 관련 Chromium 검사: **4/4 통과** (`stable.log`). 실제 대국/재접속과 통제 상태 검사는 위 구분을 따른다. 새 UI의 메뉴 Escape 뒤 대기 프리무브 유지도 포함한다.
- 최종 전체 회귀 결과는 아래에 별도로 기록한다.

캡처와 `geometry.json`은 `0090bdc`와 동일한 소스의 수정 후 관련 검사에서 생성했다. 200% 캡처는 CSS zoom 검사이며 브라우저 메뉴의 네이티브 확대나 물리 모바일 검증으로 표기하지 않는다. 보존된 흑 대국의 설정 접힘 요약은 **새 대국을 시작할 설정**이고, 진행 중 시간은 보드 위 시계에 표시한다.

- `cc5038c` 전체 회귀: **504 통과 / 8 실패**. 시작 전 PC 보드 높이 2건 및 옛 `.board-panel .row` 구조를 찾던 색상 회귀 6건. 후자는 `#gameMatchup`로 요소를 찾고 설정을 펼치도록 변경하되 색상/실패/복원에 대한 기존 단언은 모두 유지했다.
- `0090bdc` 관련 Chromium 회귀: **23/23 통과** (`correction.log`). 활성 대국뿐 아니라 설정을 펼친 시작 전 PC 높이 조건도 포함한다.

## 최종 결과

`0090bdc4abff1da2e3d0d9580746c26857ebc2f0`에서 **전체 512/512 통과** (248+264, exit codes `[0,0]`, 548.25초). `full-suite-0.log`, `full-suite-1.log`, `full-suites.json`에 전체 파일 목록과 결과를 보존한다. 기존 Starlette/httpx 지원 종료 예고 경고가 각 실행에 1개 있으며 실패는 없다. 실행 중 transport disconnected가 한 번 있었으나 명령 접근과 기존 프로세스를 확인하고 동일 실행을 끝까지 회수했다. 중복 실행하지 않았다.

구문: public JavaScript 25파일 Node 검사, 변경 테스트 3파일 Python AST, `git diff --check` 통과 (`syntax.log`). 별도 타입/린트 도구는 실행하지 않았다.

검증 이후 커밋은 이 증거 디렉터리만 추가한다. 애플리케이션과 테스트 소스는 위 검증 head와 동일하다. 전체 회귀가 갱신한 기존 다른 QA 디렉터리의 캡처들은 로컬에 보존하고 이 PR에는 포함하지 않는다.

원격 `0090bdc`의 commit status/check runs/Actions runs는 각각 0건이다. 원격 CI 통과 주장은 하지 않는다. Docker 전체 빌드, 최신 이미지 HTTP, PostgreSQL 쓰기 검증은 디스크 여유 0으로 **미실행**이다. 물리 모바일, 운영 실사용, 브라우저 자체 200% 확대 및 신규 사용자 사용성 검증도 이번 로컬 검사로 대체하지 않는다. 기존 DB나 사용자 자료 삭제, main 병합, 배포는 수행하지 않았다.
