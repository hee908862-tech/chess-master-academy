## 중간 실패와 해결

- 처음 PC 메뉴 검사3건 실패: 비모달에서 focusout의 microtask가 실제 항목 focus/click보다 먼저 메뉴를 닫았다. 포커스 전환 뒤 확인하도록 수정하고 외부 빈 영역 클릭은 호출 버튼으로 복귀한다. 메뉴 열기만으로 공통 tab()을 호출하지 않는 회귀를 유지했다.
- 새 홈 검사2건은 가능한7일 확인을 우선하도록 구현했는데 테스트가 추천 훈련을 기대한 경우였다. 상태별 우선순위 계약에 맞춰 기대값을 수정했다.
- 첫 전체 실행: **409통과/6실패,758.82초** (`0e7a515`). 4건은 ID 없는 축약 보고서의 설명 맵 생성 KeyError로, 기존 기록을 보존하고 설명만 생략하도록 수정했다. 2건은 저장 경로 검사에서 새 ‘직접 고르기’를 먼저 펼치도록 동선을 갱신했다.
- 두 번째 전체 실행: **414통과/1실패,696.25초** (`98dda62`). 실제24문항·추천5개·재진단까지는 통과했으나 저장 상태 재조회 응답이 그 사이 연 이전 기록을 다시 닫았다. 열린 상태와 선택한 보고서를 응답 후 유지하고, 계정 해제 때는 닫도록 수정했다. 지연 응답 재현을 포함한 관련17개가 통과했다. 최종 전체는 격리된 두 테스트 프로세스로 전체 파일을 빠짐없이 나누어 검증하며 목록을 보존한다.
- 로컬 빌드의 기본 Buildx 설정 경로가 읽기 전용이어서 기존 지원 `/tmp/cma-buildx`로 변경했다. 앱 시작 직후 HTTP 연결 거절은 health 준비 후 재검사했다. 보조 이미지 검사 스크립트의 계정 대문자화/완료 응답 total 참조와 캡처 전 비동기 재렌더 대기를 수정했다. 이 중간 실패를 통과로 기록하지 않았다.
