# PR16 독립 검토 후 최소 수정

기준 head: `b6c7c15cd5652320ec8619aa8b1a97bfa1acc5d0`.

분야별 시각 요약을 기본 노출하고 추천 훈련 앞에 배치했다. 점수/미측정/추가 확인 상태와 막대는 바로 보이며 관찰 수·불확실성 설명은 각 카드에서 펼친다. 같은 설명을 반복하지 않고 기존 추천 이유와 연결은 유지한다. 점수식·API·저장 데이터는 변경하지 않았다.

추가 검토에서 높이480px, 글자150%일 때 PC 메뉴가 하단36px 넘치는 결함을 재현했다. 메뉴를 연 뒤 실제 높이로 상단 위치를 보정했다. 이 변경은 위치만 조정하며 메뉴 이동·엔진·학습 로직은 바꾸지 않는다.

## 범위와 증거

- Chromium 제어 응답을 사용한 분야 요약/추천 연결 검사 및 기존 성장 화면 회귀. 320–1440px, 빈 결과/오류/이전 기록을 포함한다.
- rules-first 홈 버튼은 실제 로컬 임시 계정의 시작 수준 설정과 기초 API를 이용해 동일 권장 기초 제목/포커스에 도달하는지 확인한다.
- 진행 중 진단·훈련·기억 확인 홈 버튼 목적지, 이전 계정의 대기 응답이 도착해도 새 계정의 홈/결과가 유지되는지 제어 응답으로 확인한다.
- PC 메뉴900×420 및1280×480/글자150%, 끝 항목 포커스·Escape·390px 전환 후 모바일 모달과 포커스 복귀를 확인한다. 글자 확대는 CSS로 재현한 것이며 브라우저 네이티브 줌 인증이 아니다.
- `summary-390.png`, `summary-1280.png`는 제어 보고서 전체 캡처, `menu-*.png`는 메뉴 캡처다. 이미지 픽셀을 직접 확인한다. 물리 모바일·운영·교육 효과는 미검증이다.

기존 전체416/PG16/Docker 결과는 이전 소스 `bf1fea9`의 검증이며 이번 후속의 전체 재검사로 집계하지 않는다. 이번은 표시/위치의 좁은 변경으로 관련 Chromium·구문 검사를 수행한다.

중간 추가 검사7개 중5통과/2실패: 하나는 위 메뉴 위치 결함, 하나는 같은 임시 계정의 rules-first 설정이 다음 기억 확인 테스트에 남아 우선한 검사 격리 문제였다. 후자는 기초 설정 응답을 명시적으로 분리했으며 기존 목적지 검증을 약화하지 않았다.

최종 관련 검사: 요약/성장26통과(100.04초), 탐색/추가19통과(62.24초), 총45통과. JavaScript2개 구문, Python테스트2개 AST, git diff 공백 검사 통과. 최종 코드의 관련 검증이며 전체/PG/Docker는 재실행하지 않았다.
