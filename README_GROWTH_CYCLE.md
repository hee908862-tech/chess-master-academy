# 분야별 진단에서 성장 확인까지

기준 main `8e48bd871a3ad0d16edbb282e83504c5c7f19978`. 별도 수정 브랜치이며 부모 검토 전 병합/배포하지 않는다. 기존 계정·PIN·로그인·문제은행·저장 기록을 유지하며 보류한 로그인 정책은 포함하지 않는다. 운영 데이터에 접근하거나 초기화하지 않는다.

## 사용자 흐름과 설계 선택

홈 → 24문항 균형 진단(간이 12문항 선택 가능) → 분야별 상태 도형·막대·관찰 설명 → 추천 훈련 5개 → 새로운 문제로 재진단 → 프로필 성장 그래프. 한계 설명과 문항별 근거는 펼쳐보기로 이동했다. 첫 진단이나 전부 미응답이면 가짜 0점/강약점 대신 쉬운 훈련과 분야 추가 진단을 제공한다. 동점은 고르게 나타남, 전부 완주는 상위 난도 확인, 전부 미완주는 기초 연습으로 안내한다.

24문항은 제품 기본값으로 선택한 6영역×2난도×2문항이며 검증된 심리측정 기준은 아니다. 12문항은 각 난도 1문항인 간이 진단으로 점수 선을 24문항과 연결하지 않는다. 시작 국면과 후속 국면 전체를 교차 모드 노출 목록에서 제외한다. 진행 중 스냅샷과 구형 진단은 기존대로 재개한다. 새 평가에서는 분야명·난도·남은 수순 길이를 숨긴다. 분야를 예측하기 어렵도록 새 진단 문항 순서를 섞는다. 기본 난도 구성은 비교를 위해 고정하고, 추가 진단만 수행에 따라 600–1200 / 900–1500 / 1800–2400으로 조정한다. 무한한 적응형 문항반응 모델을 구현했다는 의미가 아니다.

### 실제 문제은행 점검

전체 합법 수순 인덱스에서 확인한 후보 수(영역 간 중복 가능):

| 분야 | 전체 | 600–1200 | 1200–1800 | 1800–2400 |
|---|---:|---:|---:|---:|
| 메이트 | 13,000 | 4,623 | 4,807 | 3,199 |
| 이어지는 수 읽기 | 38,656 | 10,449 | 13,459 | 11,529 |
| 포획·교환 | 16,912 | 4,664 | 6,293 | 4,727 |
| 방어 | 3,270 | 601 | 953 | 1,182 |
| 승격 | 3,187 | 898 | 942 | 1,018 |
| 종반 전술 | 5,222 | 1,892 | 1,583 | 1,314 |

분류는 메이트 종착, 첫 포획, 후속 수 존재, 승격 선택, defensiveMove 태그, 10기물 이하 종반 전술로 규칙 확인한다. 상대 응수 이후 수순 실행이지 머릿속 선계산 전체를 직접 측정하는 것은 아니다. 전략·장기 계획과 일반 종반 운영의 검증 과제는 없으므로 **측정 전(null)**이다. 원본 퍼즐 난도는 사람의 종합 실력 레이팅이 아니다. 누적 노출로 한 분야의 후보가 소진돼 균형 문항 구성을 채울 수 없으면 새 기본 진단을 저장하지 않고 기존 결과·훈련을 유지한다. 일부 응답만 수행한 진단은 관찰 조건을 충족하지 못한 점수를 비교 선에서 제외한다.

## 분야별 점수와 스냅샷

`growth-v1`, `journey-v4`, `competency-v2` 및 안내 조건·진단 모드를 저장한다. 영역 점수는 목표를 완수하면 1(더 짧은 합법 메이트 포함), 부분 수행이면 `correct_plies / total_plies`를 난도별로 평균낸 뒤 두 난도에 동일한 50% 비중을 준 0–100 수행 지표다. 첫 시도·앱 내 새 국면·무도움의 완료/부분 수행/확인된 오류만 사용한다. 미응답, 미검증 대안, 노출된 위치, 도움 받은 응답은 0으로 대체하지 않는다. 한 난도의 관찰이 없으면 점수는 null이다. 양쪽 난도에서 각 2개 이상 관찰되어야 비교 조건을 충족한다.

원본 수와 다른 착수는 짧은 Stockfish 탐색에서 양쪽 깊이 10 이상이고 200cp 이상 손실이 관찰될 때만 오류 근거를 추가한다. 메이트 평가를 임의 cp로 변환해 진단 오답을 확정하지 않는다. 평가 누락·낮은 깊이·엔진 사용 불가·분석 슬롯 사용 중에는 기존대로 판단 보류다. 엔진 근거와 실제 응답은 내부 문항에 보존한다. 이 짧은 탐색은 심판 수준의 정답 완전성을 보장하지 않는다.

참고 범위는 각 난도의 bounded-mean Hoeffding 폭을 평균낸 보수적 범위다. 독립 무작위 표본이라는 가정이 실제 수행에서 완전히 충족되거나 사용자 실력에 대해 보정된 신뢰구간이라고 주장하지 않는다. 적은 관찰에서 넓은 범위를 표시하며, 수치 차이를 확정적인 교육 효과로 표현하지 않는다. ‘잘한 부분’은 이번에 2개 이상 완주한 분야의 관찰이며 상대적 순위/일반 능력 인증이 아니다. 같은 결과라면 약점 순위를 만들지 않는다.

완료 시 점수·문항 수·난도별 수·조건·버전·직전 훈련 완료 수를 스냅샷으로 저장한다. 같은 scoring/assessment/competency 버전, 문제은행 SHA-256, mode, scope의 충분한 관찰이 인접할 때만 선을 잇는다. 첫 진단은 점 하나, 미측정은 빈 곳, 간이/부분은 별도 점, 구버전은 별도 기록이다. 구형 기록의 점수를 소급 생성하지 않는다. 진행 중인 재진단과 저장 실패는 이전 스냅샷 및 이미 획득한 훈련 완료권을 지우지 않는다.

## 추천 훈련 단위와 서버 검증

기본 5과제는 우선 연습할 두 분야에 원본 연습+새 적용을 각각 배치하고 다른 분야 새 적용 1개를 더한다. 차이가 없는 경우 균형 연습이며 선택 분야를 약점이라고 부르지 않는다. 원본 2개와 새 적용 3개는 서로 다른 콘텐츠다. 원본 과제의 개념·힌트·답안과 상대 응수 재생을 기존 훈련실에서 제공한다.

`learning_progress.cycles[diagnosisId]`에 할당 card ID와 완료 session ID·국면·도움·시각·실제 착수 수를 저장한다. 페이지 열기, 완료 버튼, 같은 요청 재전송, 같은 과제/국면 반복, 과거 주기 과제로 수를 늘릴 수 없다. 새 적용도 전체 수순 과제다. **성공적으로 전체 수순을 직접 둔 것**이 1단위이며 도움을 본 뒤 완주도 학습 완료로 인정하고 공개 표시한다. 따라서 독립 숙달 실패가 영구 잠금으로 이어지지 않고 답안을 보며 연습할 수 있다. 무응답 클릭만으로 해제하지 않는다.

현재 진단의 5개 완료를 서버가 확인해야 새 균형/간이/구형 기본 진단을 시작할 수 있다. 분야별 추가 관찰은 계속 가능하지만 주기를 재설정하지 않는다. 기존 7일 지연 재평가는 ‘기억 유지 확인’으로 분리해 일반 재진단 해제 조건과 혼동하지 않는다. 기존 경로·학습 이력도 유지한다.

## AI 대국 분석과 레이팅 제한

프로필에서 저장된 대국의 ‘이 대국 분석’을 누르면 별도 작업에서 실제 Stockfish를 실행한다. 자동 가짜 수치는 생성하지 않는다. 상태는 분석 전/대기/진행/완료/일부/실패이며 실패 또는 재시작 뒤 120초 경과한 작업은 재시도할 수 있다. 한 프로세스당 분석 1개, 엔진 Threads 1 / Hash 16MB / 국면당 0.08초 및 depth 14 상한 / 사용자 최대 80착수다. 추가 요청은 짧은 재시도 안내로 제한하고 DB 트랜잭션 안에서 엔진을 기다리지 않는다. 여러 서버 프로세스 전체를 통합한 분산 작업 큐는 아니다.

사용자 색 관점의 전후 cp를 일관되게 비교한다. `내 수 품질 = mean(100 * exp(-max(0, before_cp-after_cp)/200))`이며 공개 서비스 정확도 방식의 복제가 아니다. 메이트 평가는 ±10,000cp로 bounded 표현하고 별도 표시를 저장한다. 이는 승리 가능성이나 사람의 인지 난도 보정 모델이 아니므로 이긴/진 대국 및 국면 구성이 달라지면 수치가 왜곡될 수 있다. 원시 전후 평가, 깊이, 엔진 이름/버전, 설정, 사용자 착수 수를 저장한다.

10착수 미만, 도움/무르기, 과거 도움 기록 미확인, 중도 종료, 깊이 8 미만 또는 일부 분석은 대표 누적 평균에서 제외하고 개별 참고로 표시한다. 대표 평균은 동일 버전의 적격 대국을 사용자 착수 수로 가중한다. **검증된 사람 레이팅 환산 모델이 없어 추정 레이팅은 항상 산출 보류**다. 정확도→Elo 선형 변환, AI 난도→공식 레이팅, 임의 오차범위는 없다. 게임 수가 늘어도 이 보류를 자동 해제하지 않는다.

새 `game_analysis` 테이블만 추가한다. 기존 대국 JSON을 재작성하지 않는다. 작업은 요청의 초기화 세대를 이어받고 새 작업 ID와 상태 CAS로 오래된 작업 덮어쓰기를 막는다. 계정 초기화 기능의 범위에는 파생 분석도 포함하되 **운영 계정 초기화는 실행하지 않는다**.

## 문구·레이아웃

홈 문장을 짧고 자연스럽게 바꾸고, 거대한 제목의 인위적인 폭 제한과 중복 학습 영웅 영역을 정리했다. ‘공통 태그 새 문제’는 ‘같은 원리의 새 문제’, 과도한 설명은 펼쳐보기다. 누적 활동을 가짜 능력 퍼센트로 표시하던 막대를 실제 횟수로 바꿨다. 모바일 프로필의 145px 최소 통계 열 넘침과 200% 확대에서 계정 입력 열이 지나치게 좁아지는 문제를 실제 캡처로 확인해 수정했다. 가로 넘침 검사만으로 충분하지 않아 확대 입력 폭 검사도 추가했다.

브라우저 검사는 320/360/390/430/768/900/1024/1280/1440px, 긴 한국어, 완료·미응답·부분·오류·로딩 및 비교 불가능한 그래프 점을 포함한다. 200%는 Chromium CSS zoom으로 재배치를 점검한 것이며 실제 OS 배율/모든 브라우저 네이티브 확대/물리 기기 검증과 같다고 주장하지 않는다.

## 검증 및 참고

최종 실행 수·이미지·PostgreSQL 결과는 검증 완료 뒤 아래에 기록한다. 중간 실패(기존 모바일 프로필 통계 넘침)와 수정은 숨기지 않는다. 기존 검사에서 제품 문구·기본 24문항 요구와 충돌하는 기대는 의미를 보존해 갱신한다.

2026-10-20 공식 자료를 직접 읽었다. [Lichess 정확도](https://lichess.org/page/accuracy)는 국면 난도와 정확도·레이팅 관계가 단순하지 않으며 게임 집계가 단순 수 평균과 다름을 설명한다. [Chess.com CAPS2](https://support.chess.com/en/articles/8708970-how-is-accuracy-in-analysis-determined)는 자체 정확도 방식이다. [Game Rating 안내](https://support.chess.com/en/articles/10773754-how-is-game-rating-calculated-in-game-review)는 봇 상대 수행 추정의 불안정성을 설명한다. [Lichess 레이팅 시스템](https://lichess.org/page/rating-systems)은 서로 다른 모집단/시스템의 점수를 직접 비교하지 않도록 안내한다. 이 앱의 공식 레이팅이나 외부 서비스와 동등한 정확도를 검증한 출처가 아니다.
