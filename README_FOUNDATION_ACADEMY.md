# 기초 아카데미와 학습 진입 개편

기준 main `ebe5371e1716a2b2d0d75409506a940e5bd11f37`. 운영 계정·기록·문제은행·로그인 정책을 변경하거나 초기화하지 않았다.

## 콘텐츠와 저장

자체 작성한 10개 과정, 26개 착수·판단 단계를 추가했다. 기존 퍼즐의 이름을 바꾸지 않았으며 기초 과제는 전술 퍼즐 점수와 별도다.

| 과정 | 실제 상호작용 |
|---|---|
| 룩과 비숍 | 직선·대각선 이동, 내 폰에 막힌 경로 |
| 나이트와 퀸 | 초기 배치에서 나이트 뛰어넘기, 퀸 대각선 |
| 폰과 잡기 | 두 칸 전진, 대각선 잡기, 룩으로 잡기 |
| 킹과 체크 | 안전한 한 칸, 피하기·가로막기·체크 기물 잡기 |
| 메이트·스테일메이트 | 직접 메이트 만들기, 체크 유무와 합법 수 판단 |
| 캐슬링 | 짧은/긴 캐슬링 착수, 공격받는 경로 판단 |
| 프로모션 | 퀸·나이트 승격 선택과 다른 합법적 승격 피드백 |
| 앙파상 | 즉시 잡기 착수, 권리 소멸 후 불가 판단 |
| 가치·보호 | 룩으로 내 말 보호, 공격받는 비숍 피하기 |
| 기본 대국 진행 | 백의 3수와 자동 예시 응수, 흑 시점의 첫 응수 |

규칙은 [FIDE 기본 규정 1–5조](https://handbook.fide.com/chapter/E012023)와 대조했다. [Chess.com 초보 가이드](https://www.chess.com/learn-how-to-play-chess)도 열어 확인했으며 문구·예시를 복제하지 않았다. 전체 대회 규정, 모든 무승부 유형, 전략 숙련을 다루지 않는다고 UI에 표시한다. 나이트의 자기 말 착지 금지, 폰의 중간 칸, 캐슬링 이동 이력/킹 경로, 앙파상 시점/킹 노출, 승격의 네 선택과 잡힌 말 무관, 메이트와 스테일메이트의 체크 차이를 설명한다. 모든 FEN의 python-chess 유효성 및 예시 착수 합법성을 검사한다. 이는 임의 국면의 모든 도달 경로를 증명하는 검사로 과장하지 않는다.

저장은 기존 progress의 새로운 `foundation_v1` 키만 사용한다. 과정별 단계·예시 수순 위치·피드백·완료 단계 집합, 현재 과정과 전역 revision을 저장한다. 계정별 기존 CAS 저장을 사용하고 늦은 요청은409로 거부한다. 중복 완료·복습은 완료 수를 늘리지 않는다. 과정 전환·새로고침·컨테이너 재시작에도 이어간다. 일반 GET은 저장하지 않는다. 기초 완료를 진단 점수, Elo, 표준 추천5개 또는 7일 검증 크레딧에 합치지 않는다. rules 선택 사용자는 기존 빠른4단계 또는 전체 기초 완료 후 기본 입문 진입이 가능하며, gentle/표준 gate 정책은 별도로 보존한다.

## 사용자별 동선과 화면

- 규칙을 모르는 사용자: 명시적으로 ‘룰부터 배우기’를 선택한 때만 아카데미로 이동. 다음 권장 제목에 포커스·스크롤, 카드에는 ▶ 텍스트와 테두리 강조. 새로고침은 강제 이동하지 않는다.
- 룰만 아는 사용자: 기초 선택·복습 또는 입문 관찰을 자발적으로 선택한다.
- 경험 있는 사용자: 선택 변경 시 아카데미 강제 이동 없음. 기존 표준 진단·전술 훈련 유지.
- 복귀 사용자: 기초 이어하기와 기존 전술 과정 이어하기를 분리. 저장된 진단·훈련으로 돌아가기 제공, 그 상태를 기초 선택이 덮지 않는다.
- PC/모바일: 주요 메뉴 순서는 홈·아카데미·진단·훈련실, 나머지는 기록과 보조 도구로 묶음. 기초는 첫 영역, 전술 과목은 별도 영역·검색. 전술의 기존 ‘입문’은 규칙 초보 과정이 아닌 문제 난도임을 명시. 반복 제목 제거. 작은 화면은 한 열이며 설명과 전체 목록은 펼쳐 읽는다.
- 키보드: 추천/단계 제목 포커스, 보드의 이름 있는 버튼, 기물·도착 칸 목록과 승격 선택 대안, 상태 읽기·오류 재불러오기. 작은 체스판 칸은44px보다 작을 수 있으므로44px 이상 목록 입력을 함께 제공한다. reduced-motion 스타일을 적용한다. 스크린리더 전 제품의 접근성을 인증한 것은 아니다.

## 검증과 한계

실제 Chromium은 임시 계정과 격리 로컬 DB를 사용한다. 320/400/1280px에서 초보자 이동·추천 포커스·착수·목록 입력·새로고침·기존 진단/훈련/메이트 과정 보존을 검사한다. 전체26단계를 실제 보드와 판단 버튼으로 완주하고, 기존 표준0/5 주기와 통계가 그대로임을 검사한다. API는 잘못된 이동 이유·합법적 대안·복습·계정 분리·중복/동시 제출·GET 비변경을 검사한다.

- 초기 API4개, 관련 브라우저9개, 화면 밀도 조정 후 관련9개 통과.
- PostgreSQL15개 통과: 신규 기초 CAS·재시작 복원·계정 분리 포함.
- 실제 Docker1CPU/512MiB·임시 PostgreSQL HTTP: 기초 수순 중간 복원, 기존 진단/훈련/과정 보존, 별도 계정 확인 통과. OOM 없음. 기존 복기·오프닝/학습 이어하기 HTTP 회귀도 같은 이미지에서 통과했으며 복기 검사 메모리 최고400,420,864바이트였다.
- Python AST86파일, JavaScript node --check20파일 통과. 전용 타입/린트 설정이 없어 별도 타입/린트는 미실행.
- 실제 새 이미지의400px Chromium에서 reduced-motion의 scroll-behavior=auto, 첫 권장 버튼 높이44px 이상·하단 메뉴 위 노출·가로 넘침 없음을 추가 확인했다. 320/400/1280px 화면과 추천 포커스 캡처를 직접 열어 확인했다.
- 화면 검토 중 변경한 소개·목록 접기를 반영하기 위해 첫 전체 실행을52통과 시점에 중단했다. 이를 전체 통과로 표시하지 않는다. 최종 전체 실행은 아래 로그로 별도 기록한다.

검증 증거: [docs/qa-foundations](docs/qa-foundations). 최종 전체 pytest는 **372통과**, 실패/건너뛰기0, 645.52초, 종료 코드0이다. 경고1개는 Starlette TestClient 사용 중단 예고다. `git diff --check`도 통과했다. 원격 CI는 최종 push 후 조회하며 PR/최종 보고에 기록한다. 실물 모바일, Safari, 스크린리더와 운영 실사용은 미검증이며 독립 리뷰·배포 후 확인한다. 이 작업에서는 병합·운영 배포를 실행하지 않는다.
