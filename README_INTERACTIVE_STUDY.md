# 진단 흐름 정리와 보드 기반 복기·오프닝 학습

기준 main `d7e73bde78ae4a2c913ba3f5db60833cda3e023d`. PR #8 이후 별도 수정 브랜치이며 **리뷰 전 병합하지 않는다**. 기존 계정/PIN/기록/문제은행을 보존하며 로그인 정책을 변경하지 않는다. 아래 검증은 임시 로컬 계정과 격리 DB에서 실행한다.

## 진단과 추천 훈련

진행 중 진단의 저장 상태 조회가 이전 완료 결과를 먼저 렌더링하는 코드 경로를 확인했다. 현재 문제 아래에는 현재 세션만 표시한다. 이전 보고서는 접힌 ‘이전 완료 진단 기록’에서 읽기 전용으로 보존하고, 이전 훈련 진행률·재진단 버튼을 다시 만들지 않는다. 화면 이동 및 계정 변경은 요청 세대를 변경하여 늦은 응답이 현재 세션을 덮지 못하게 한다.

관찰이 있지만 양쪽 난도 자료가 부족하면 ‘추가 확인 필요’와 기초·응용별 관찰 수, 점수 및 비교에 필요한 조건을 표시한다. 실제 검증 과제가 없는 전략은 ‘미측정’, 응답이 없는 분야는 ‘아직 응답 없음’이다. 건너뛰기·판정 불가·동등 첫 수는 전체 수순 수행 점수에서 제외한다.

홈과 훈련실의 주 흐름은 진단 → 추천5개 → 재진단이다. 이전 4단계 경로는 삭제하지 않고 접힌 선택 연습으로 남긴다. 대국/퍼즐/과정 집계와 완료 진단/응답 문항/추천 과제 완료를 분리한다. ‘도움 없이’ 등 자연스러운 표현으로 고치고, 기술 버전·태그·출처는 상세 근거에 둔다. 완료 추천 카드의 배경·경계·문자 대비를 높이고 중복 홍보 영역을 줄였다.

## 대안 판정 조사

운영 QA의 6정답·4다른 합법 수·14건너뛰기라는 관찰은 전달된 보고다. 운영 요청 로그나 엔진 깊이가 없으므로 그때 네 건 모두 보류된 원인을 확정하지 않는다. 기존 코드에는 균형/간이 모드에서만 대안을 분석하는 제한과, 엔진 없음·진단 슬롯 사용 중·공통 엔진 사용 중·낮은 깊이·메이트 평가·오류를 모두 `None`으로 반환하는 경로가 있었다.

새 기록에는 `alternative-v2` 정책, 실제 엔진/설정/깊이, cp 또는 mate 평가와 보류 사유를 보존한다. Threads1/Hash16, 국면당0.3초·depth16 상한, 양쪽 최소depth10이다. 공통 엔진1개 제한과 0.15초 획득 제한은 유지한다. DB 쓰기 트랜잭션 밖에서 분석하고 저장 시 session/revision을 다시 검증한다. 모든 새 진단 모드에서 동일한 선택적 근거를 수집한다. 과거 결과는 재채점하지 않는다.

- 두 cp 평가가 충분한 깊이를 갖고 200cp 이상 손실이면 명확한 오류 근거로 기록한다.
- 35cp 이하 차이는 ‘평가가 비슷한 대안’으로 표시한다. **첫 착수의 근사 평가이며 전체 수순 완주·유일 정답·실력 인증이 아니다. 점수/완료 크레딧을 부여하지 않는다.**
- 그 사이 차이, 낮은 깊이, 엔진 실패/경합 등은 이유를 표시하며 판단을 보류한다. 기존 ‘이 분야 더 확인하기’로 새 관찰을 얻을 수 있다. 과거 응답을 재제출해 점수를 바꾸는 기능은 추가하지 않았다.
- mate 값을 임의 cp 상수로 바꾸지 않는다. 규칙상 즉시 메이트는 기존대로 인정하고, 그 외 mate 평가는 증명 부족으로 보류한다.

`OZElq`의 시작은 원본 첫 수 ...Nxe4를 적용한 뒤 백 차례다. `Qc3(d2c3)`는 실제 Stockfish에서 큰 손실로 확인했다. `d3e4`, ...`e7g5`, `d2g5`는 **순차 기준 수순**이다. 마지막 수를 초기 위치의 대안으로 오해하지 않는다. 실제 균형 진단 API에서 해당 국면을 임시 계정에 준비하여 Qc3 오류 판정과 엔진 자원 경합 때 이유가 있는 보류를 검사한다. 원래 운영 당시 자원 상황은 미검증이다.

## 복기 탐색

`/study/position`은 받은 초기 위치와 수순을 python-chess로 재생하며 합법 수·승격·캐슬링·앙파상·종료를 확인한다. 복기는 원본 시작부터 선택 위치까지의 이력을 함께 보내 반복 무승부 조건도 유지한다. 분기 이전/다음·다른 수로 가지치기·초기화·원본 복귀·선택적 현재 차례 엔진 응수를 제공한다. 흑 시점을 보존하고 승격 선택기를 재사용한다. 반복/50수의 청구 가능한 무승부도 탐색 종료로 안내한다.

분기는 브라우저 메모리에만 있고 원본 기보를 수정하지 않는다. API는 인증 확인 외에 상태 저장·대국 종료·레이팅·훈련 완료 함수를 호출하지 않는다. 새 위치·원본 복귀·화면 이동·로그아웃마다 요청 세대를 바꾸어 늦은 엔진 응답을 무시한다. 취소는 UI 결과 반영 취소이며 이미 실행 중인 최대0.2초 엔진 계산을 강제 종료하지 않는다. 새 수를 둘 때 미래 분기는 잘라내며 다른 분기 전체를 영구 보관하는 편집기는 아니다.

탐색 모드는 후보 수와 다음 수 해설을 보여주며 혼자 풀기는 둘을 숨긴다. 양쪽 말을 직접 두는 방식으로 상대의 여러 대응을 비교한다. 독립 숙달/성공 점수는 만들지 않는다. 계정 progress의 새 `opening_study` 필드에 강의ID·수순·모드·방향·revision만 저장하며 기존 CAS로 동시 덮어쓰기를 거절한다. 대국·진단·추천훈련 통계와 별개다. 참고 검색의 수순은 저장 강의가 아니며, 저장 기능은 27개 강의에 적용된다. 기존 오프닝 실습·기록은 접힌 보조 영역에서 보존한다.

## 독립 리뷰 후 보완

- 과거 보고서의 읽기 전용 상태를 지연 생성 콜백과 성장 결과에도 전달한다. 훈련/추가 진단 액션을 생성하지 않으며 진행 중 진단의 훈련 핸들러도 방어한다. 실제 브라우저에서 상세 펼침 후 활성 버튼 없음, 학습 POST 없음, 상태 불변을 확인했다.
- 새 계정의 오프닝 첫 방문은 기본 강의를 자동 준비한다. 저장 위치 복원 대기 중 보드에 새 수를 두면 복원 의도도 취소한다. 실제 브라우저에서 저장 A→현재 B→복원 GET 지연→새 착수 C→옛 응답 해제 후 C 유지와 다음 합법 착수를 확인했다.
- 계열 일반 개요는 현재 위치의 계획이 아님을 명시한다. 강의 끝에는 실제 폰 배치와 각 분기의 종료 계획만 보여 준다. 미등록 수/다른 강의 위치에는 선택 강의의 계획을 표시하지 않는다. 베를린·교환 변형에서 사라진 d폰을 다시 전진하라는 일반 계획이 나타나지 않는다. 드래곤 c파일은 반열림, 나이도프19반수는 흑 킹 e8, 베를린 Nc3는 나이트 전개, 오픈형 d6는 e5 제어로 수정했다. 27개 종료 위치와 미등록 위치, 해당 기물 배치를 규칙 엔진으로 검사했다.
