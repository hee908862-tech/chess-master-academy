# PR #8 독립 검토 후속 수정

기준 head `1836224fa0d674b87a355bae19be757d57984f67` 이후 변경이다. 운영 계정/DB/문제은행/로그인 정책을 변경하거나 초기화하지 않는다. 새 브랜치 head는 검토용이며 병합·배포하지 않는다.

## 앱 내 추정 레이팅 · 베타

사람 Elo 환산을 구현한 것이 아니다. 정확도와 독립적으로 **완료 대국의 사용자 관점 승/무/패**만 사용하는 0–100 내부 제품 지표다. 무제한/래피드/블리츠/불릿을 별도 series로 보관한다. 첫 10판 전은 ‘잠정’, 이후에도 항상 ‘미보정 베타’이며 인구집단 실력 또는 공식 레이팅으로 검증됐다는 의미가 아니다.

- 버전 `app-rating-beta-v1`, 계산 초기값 50, K=8, 기대점수 `E=1/(1+exp((AI기준점-R)/12))`, 갱신 `R'=clamp(R+8*(S-E),0,100)`. S는 승1/무0.5/패0. 저장은 소수 셋째 자리, 표시는 첫째 자리.
- 50은 척도의 중간인 제품 초기값이다. 미평가 상태를 50점 실력으로 표시하지 않고 첫 반영 대국 이후 값부터 그래프에 점을 만든다. K8은 한 대국 변화가 8점 미만이도록 제한하려는 제품 선택이며 표본으로 학습/보정한 값이 아니다. scale12는 내부 기준점보다 12점 높을 때 기대점수가 약0.73이 되는 완만한 갱신 규칙이다.
- 고정된 Stockfish **17.1** + 적용 성공한 기존 난도 설정에만 내부 기준점을 둔다. level1~10 기준점은 `20+5*(level-1)`(20~65). 난도 증가를 내부 순서로 표현하면서 승패 갱신 여지를 남기려는 초기 설계값이다. 이 값은 실제 사람/AI 대국으로 보정하지 않았으며 UCI_Elo 설정의 숫자를 사람 레이팅으로 사용하는 것도 아니다.
- 실제 AI 호출마다 엔진 이름/버전, Threads1·Hash16, UCI_LimitStrength·UCI_Elo, 허용 시간, level, 설정 적용 여부, fallback 여부, 착수 위치(ply), 실제 착수 여부(played), 정책 버전 `ai-execution-v1`, 내부 기준점을 저장한다. 설정 실패/미지원 엔진 버전/기록 누락/혼합 설정은 제외한다. cma-minimax fallback도 사용 사실을 보존하지만 미보정 대체 AI이므로 제외한다.
- 도움 정보가 완전하고 힌트·무르기 이력이 없으며 사용자 실제 착수가 있는 정상 규칙 종료·기권·시간패/시간승만 반영한다. 정상 패배를 ‘중단’으로 제외하지 않는다. 새 대국으로 폐기한 미완료 대국은 저장된 완료 결과가 아니므로 반영하지 않는다. AI 계산 뒤 시계가 만료돼 실제 수를 두지 못한 정상 시간승도 포함하며, 마지막 계산 기록은 played=false로 보존한다. 시계 속도/서버 성능의 영향도 보정되지 않은 내부 지표라는 한계가 남는다.

### 저장·호환성과 중복 방지

새 대국 active JSON에 `ai_execution`을 추가한다. 완료 archive에 실제 AI 기록과 `app_rating`(version, eligible/reasons, result, clock mode, anchor, before, after, expectation, outcome, K, scale, sequence)을 보존한다. 계정 progress JSON의 `app_ratings[time_mode]`에 현재 버전·값·반영 수를 보관한다. 기존 progress CAS/트랜잭션에서 games와 지표를 함께 저장하며 동시 같은 필드 갱신은 충돌로 거절된다. SQL 테이블 삭제/재작성 마이그레이션은 없다.

분석 버튼·재조회는 지표를 갱신하지 않는다. session ID와 이미 저장된 갱신 기록으로 archive 중복도 방어한다. 기존 대국에 실제 AI/도움 정보가 없으면 GET 응답에 제외 사유만 덧붙이며 저장 JSON을 소급 수정하거나 추정 점수를 넣지 않는다. 기존 진행 중 대국도 완전한 호출/도움 기록이 없으면 제외한다. 코드상 이 progress 내 파생 필드도 기존 계정 기록 초기화 대상에 포함된다. 운영 초기화는 실행하지 않는다.

## 재현과 수정

1. **해제권한 재사용:** 이전 head 모듈을 임시 SQLite에서 실행했다. 간이 진단 뒤 격리 완료권한 상태를 준비하고 basic 완료→해제권한 유지→다시 basic HTTP200을 확인했다. 현대 주기가 존재하는 계정의 새 legacy basic 요청은 이제 HTTP409로 거절한다. 기존 진행 basic 세션의 재개·완료는 보존한다. 균형/간이 새 주기에는 기존 5과제 조건을 계속 적용한다.
2. **종료 국면 depth0:** 실제 Stockfish의 백17착수 Opera Game 체크메이트 종료 분석이 depth0임을 재현했다. `move-quality-v2`는 규칙상 종료 국면을 별도 취급한다. 실제 체크메이트를 완성한 수는 규칙으로 최적 목표 달성을 확인해 품질100/손실0으로 기록하며, 임의 ±10,000cp로 메이트 점수를 변환하지 않는다. 스테일메이트/확정 무승부는 종료 평가0을 사용하고 종료 후 엔진 depth를 요구하지 않는다. 비종료 메이트 평가도 cp 평균에 억지로 넣지 않고 별도 기록하며 실제 수치 평균 착수 수를 표시한다. 정상 충분한 길이의 기권·시간 종료는 분석 범위·도움·깊이 조건을 충족하면 대표 평균에 포함한다.
3. **이전 분석:** v1 완료/부분 결과는 ‘이전 방식’으로 표시하고 사용자가 새 방식으로 재분석할 수 있다. 이전 원시 결과는 `previous_analysis`에 보존한다. 외부 사람 레이팅 환산은 여전히 null/보류다.
4. **기존 개념 단계 충돌:** 이전 head의 learning.js를 실제 로컬 API에 연결해 활성 추천 과제가 읽기 전용 개념 화면에 가려지고 보드가 비활성화됨을 재현했다. 활성 growth_task가 기존 path의 개념 화면보다 우선하도록 표시 조건을 분리했다. 기존 path를 삭제하지 않는다. 실제 브라우저 테스트에서 기존 경로 개념 단계를 만든 뒤 추천5개 완주 내내 path JSON이 같음을 확인한다.
5. **성장 기록 선택:** snapshot이 있는 같은 version/assessment/competency/scope/mode/corpus series를 먼저 선택한 뒤 최근12개를 그린다. 구형·분야 추가 진단은 별도 기록으로 보존하며 정식 점을 밀어내거나 선을 끊지 않는다. 같은 series의 실제 null만 gap이다.
6. **공통 엔진 자원:** 모든 서버 Stockfish 생성 지점은 `engine_budget.open_engine`을 통한다. 기본 배포의 단일 worker에서 엔진 프로세스 1개만 허용한다. 획득 대기는 0.15초이고 AI 대국은 사용 중이면 Retry-After1의 HTTP503을 반환하며 해당 착수를 저장하지 않는다. 진단 대안 평가는 판단 보류, 배경 분석은 실패/재시도 안내로 돌아간다. 무한 대기하거나 몰래 강도 불명 AI로 바꾸지 않는다. 실제 엔진 고장으로 사용한 기존 fallback은 기록하고 레이팅에서 제외한다. 프로세스 간 분산 제한은 아니므로 worker 수 증가 시 별도 자원 설계가 필요하다.

## 검증 범위

새 단위/API 검사는 백·흑 승무패, 정상 기권·시간 종료, 도움/설정실패/fallback/미지원 버전 제외, 시계별 series, 중복 archive/분석/재조회, 기존 기록 불변과 재초기화 후 복원을 포함한다. 실제 엔진 메이트17착수/스테일메이트 검사, 한 엔진 제한과 foreground 재시도 검사를 추가했다.

`tests/test_growth_real_browser.py`는 실제 로컬 API/Chromium에서 24문항 중 정답·부분 수행→결과→기존 경로 개념 단계→추천5개 실제 수순 완주→힌트 후 새로고침 재개→재진단 해제→새 주기 생성까지 실행한다. 답안 준비는 해당 테스트의 임시 SQLite만 읽는다. 서버 응답이나 핵심 버튼을 가짜로 바꾸지 않는다. [5개 완료 캡처](docs/qa-growth/real-five-tasks-unlocked.png).

최종 전체 회귀는 **308 passed**, 489.29초였다. Starlette TestClient의 httpx 사용 중단 예고 경고 1개가 있다. 이전 head의 검증 수치를 새 head 검증으로 대체하지 않는다.
