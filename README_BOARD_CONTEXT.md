# 보드 맥락·방향·프리무브 작업 기록

기준 main: `89e65955976fba0cd42a1ba6ecbf2866724d978e`. 수정 및 PR 작성만 수행하며 운영 사이트 QA, 병합, 배포는 하지 않는다.

## 조사와 구현

- 기존 진단 결과 혼재 수정은 진행 단계에서 이전 결과를 제거하지만, status 요청 대기 중 이전 내용이 잠깐 남을 수 있었다. 상태 조회와 새 진단 시작을 별도 loading 상태로 두고 이전 요약·추천·시계를 제거한다. 늦은 추천은 loading에서도 차단한다. 프로필 과거 기록과 점수 산정은 유지한다.
- 실제 Lichess 문제의 `moves[0]`를 적용해 시작 위치를 만들지만 직전 수를 API에 전달하지 않았다. 진단에는 검증된 첫 수, 퍼즐에는 현재 offset 바로 앞의 실제 수를 `opponent_last_move`로 전달한다. FEN으로 과거 수를 추측하지 않는다. 메타데이터 없는 항목은 표시할 수 없다고 안내한다.
- 흑 진단 채점의 `drawBoard`에 flip이 없어 백 기준으로 돌아갔다. 채점은 원래 문제 FEN의 플레이어 색을 사용한다. 퍼즐은 시작/다음 문제에서 플레이어 색을 저장하고 응답·힌트·완료에 일관되게 사용한다. 다음 문제는 실제 새 플레이어 색으로 변경한다.
- 프리무브는 기존 구현이 없어 `board-tools.js`에 공통 1수 예약을 추가했다. 기본 OFF이고 브라우저 localStorage에 ON/OFF만 저장한다. 대국·진단 AI 평가·v9 퍼즐/과정의 착수 요청이 상대 응답을 기다리는 동안 사용할 수 있다. 단일 진단 문항 채점, 구형 숨김 퍼즐, 오프닝/복기에는 적용하지 않는다.
- 상대 직전 수는 청록 테두리, 사용자 마지막 수/모범 답안은 기존 금색, 힌트는 초록 점선, 예약은 분홍 출발/도착 표시와 점선 경로로 구분한다. 예약 텍스트와 취소 버튼/Escape, 모바일에서도 사용할 수 있는 설정을 제공한다.
- 응답 후 현재 turn, legal 목록, 문제 ID, 세션 ID, 종료/시계 상태를 확인하고 예약을 먼저 소비한 뒤 최대 한 번 실행한다. 승격은 실제 응답이 온 뒤 사용자가 기물을 선택하며 취소/메뉴 이탈 시 제출하지 않는다.
- 새 대국/퍼즐 세션에 식별자를 추가하고 기존 진단 seed를 식별에 사용한다. move API는 선택적 session_id/expected_fen을 검사해 변경된 세션/위치 요청을 409로 거부한다. 기존 클라이언트 호환을 유지하며 기존 기록을 초기화하거나 마이그레이션하지 않는다. 식별자가 없는 과거 세션은 일반 착수는 유지하고 프리무브는 안내 후 비활성 처리한다.
- OFF/취소/메뉴 이동/로그아웃/새 문제/종료/오답/요청 실패 때 예약을 폐기한다. 무르기는 대기 중 실행하지 못하며 복원 후 세션 식별자를 유지한다. 새 대국·기권·무르기 요청 중 겹치는 입력도 차단한다.

## 검증과 범위

로컬 Chromium에서 API 응답을 제어해 대국/진단 AI/퍼즐의 예약 대기·단일 실행, OFF/취소/메뉴/불법 수/종료/세션 변경/오류 폐기, 승격 선택/취소, 시계 만료, 모바일 경로 표시를 검증한다. API 테스트는 실제 문제은행 직전 수와 FEN 일치, 세션/위치 불일치 거부 및 상태 보존을 확인한다. 이전 결과 관련 테스트는 시작/진행/완료/메뉴 왕복/새로고침/늦은 응답을 포함한다.

실행:

```sh
python -m pytest -q tests/test_board_interaction.py tests/test_qa_behavior.py tests/test_qa_browser.py tests/test_qa_followup_browser.py
python test_qa_work_regression.py
python test_v9_static.py
python -m compileall -q .
for f in public/*.js; do node --check "$f" || exit; done
git diff --check
```

운영 Work 검증과 구분한다. 실제 모바일 기기/운영 Stockfish 네트워크 지연의 전체 통합 검증은 미실행이다. 기존 계정 JSON의 동시 read-modify-write 위험은 해결했다고 주장하지 않는다. 이번 식별/위치 검사는 서버 트랜잭션 CAS나 다중 탭 동시성 보장을 대신하지 않는다.

## 사용자가 확인할 짧은 절차 (배포 후)

1. 진단 첫 문제에서 청록 표시와 직전 수 안내를 확인한다. 흑 문제에 답한 뒤 채점·메뉴 복귀에도 같은 방향인지 본다.
2. 이전 진단 기록이 있어도 새 진단 진행 중 결과 요약/추천이 섞이지 않고, 프로필 기록은 유지되는지 확인한다.
3. 대국에서 프리무브 ON → 내 착수 → AI 대기 중 다른 내 기물의 출발/도착을 선택한다. 분홍 경로가 표시되고 응답 후 합법일 때 한 번만 실행되는지 확인한다. 응답이 빠르면 예약할 시간이 없을 수 있다.
4. 다음에는 OFF/예약 취소/메뉴 이동으로 경로가 사라지고 자동 실행되지 않는지 본다. 진단 AI 평가 및 여러 수 퍼즐에서도 동일하게 확인한다.
5. 승격 예약은 응답 후 선택창에서 기물을 고르며, 메뉴 이동이나 Escape 취소 시 착수하지 않는지 확인한다.
